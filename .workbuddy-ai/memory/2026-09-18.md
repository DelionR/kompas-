## Аудит проекта quja/kompas-3d-ai-bridge и план развития

**Задача Романа:** изучить GitHub-проект `quja/kompas-3d-ai-bridge` и предложить улучшения
на основе известных MCP для конструкторских программ (EPLAN, SolidWorks и др.).

**Что сделано:**
- Репозиторий скачан (git clone падал с OOM → использован codeload tarball) и распакован в
  `kompas-3d-ai-bridge-main/` внутри рабочей папки. Прочитаны все ключевые файлы
  (`mcp/*.py`, `src/*.py`, `skills/kompas-engineering/SKILL.md`, `config/*`, `jobs/*`, `tests/*`).
- Собрана база сравнения по 4 внешним проектам: SolidWorks MCP (`just1step/solidworks-mcp`),
  EPLAN MCP (`swater-kankyo/eplan-mcp-oss`), FreeCAD MCP (`neka-nat/freecad-mcp`),
  параллельный KOMPAS-3D MCP (`dwnmf/KOMPAS-3D-MCP-bin` + статья автора на Habr).
- Изучены: спецификация MCP (2025-06-18 → 2025-11-25 → 2026-07-28) и документация АСКОН
  по API7, включая интерфейсы сопряжений `IMateConstraint` / `IMateConstraintCollection`.

**Результат:** отчёт `KOMPAS-3D_AI_Bridge_audit_plan.html` в корне рабочей папки —
аудит (P0/P1/P2 с ссылками на код), сравнительная таблица с MCP для SolidWorks/EPLAN,
24 улучшения (A1–E5) и дорожная карта из трёх волн.

**Главные выводы (полезны для будущих задач по этой теме):**
1. Сильная сторона проекта — детерминированный слой с доказательной записью
   (byte-snapshot → проверка активного PathName → Save/Close/Reopen → повторное чтение)
   и запрет на выдумывание инженерных данных. Это надо сохранять при любом рефакторинге.
2. Ключевые дефекты: `src/config.py:load_config()` не вызывается нигде — `safety.py`
   хардкодит `C:\KOMPAS_AI_WORKSPACE\*`; трассировки утекают в ответ MCP
   (`src/worker.py:250`); полные дампы топологии (до 5000 граней) уходят в контекст модели.
3. Инженерные пробелы: **нет сопряжений сборки** (только абсолютная матрица трансформа),
   **нет 2D-чертежей/штампа/DXF/спецификации**, **нет экспорта STEP** — при том что
   `SKILL.md` требует проверять STEP и спецификации. Агент вынужден идти в `kompas_run_job`.
4. `kompas_run_job` — дыра: защита построена на поиске подстроки защищённых путей
   в тексте скрипта, обходится тривиально.
5. Каталог инструментов существует в двух местах: 33 в `mcp/kompas_mcp_server_core.py`
   + 2 дописывает обёртка `mcp/kompas_mcp_server.py` поиском подстроки. Хрупко.
6. В реестре 5 действий без MCP-обёртки: `document.activate`, `document.open`,
   `document.info`, `model.components`, `view.projections`.

**Окружение (заметки):**
- `git clone` в этом окружении падает с `Out of memory, malloc failed` — для GitHub-репозиториев
  использовать `curl -sL codeload.github.com/<owner>/<repo>/tar.gz/refs/heads/main`.
- Инструмент визуализации (`read_me`/`show_widget`) в этой сессии недоступен:
  `[MCP] Failed to callTool "read_me" from server "connector-proxy": fetch failed`.
