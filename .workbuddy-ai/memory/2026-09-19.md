## Разбор: есть ли у КОМПАСа официальный MCP SDK (вопрос Романа)

Проверил сайт АСКОН, релизные заметки v25, материалы КОМПАСcon 2026 и GitHub.
Результат сведён в файл `kompas_sdk_and_mcp_landscape.md` в корне рабочей папки.

**Итог разбора:**
- Официального MCP-сервера или MCP SDK от АСКОН **нет** на сентябрь 2026.
- Официальный **SDK КОМПАС-3D есть**: 2D API (экспортные функции DLL + Automation)
  и 3D API (COM-объекты + Automation). Automation на `IDispatch`, покрывает весь
  функционал КОМПАС-ГРАФИК и КОМПАС-3D.
- Собственный ИИ-ассистент КОМПАС **в разработке**: на КОМПАСcon 2026 (4 сентября)
  Симранов показал агента, работающего через MCP, а не напрямую с ядром; Дружинин
  и Судницын встраивают агента внутрь системы со слоем **GUARD**, валидирующим
  сгенерированный код. Обе команды пришли к выводу о необходимости
  детерминированного слоя между моделью и API.
- Ловушка при поиске: организация `ascon` на GitHub — это криптоалгоритм Ascon,
  а не АСКОН.
- Сторонние MCP-проекты: `dwnmf/KOMPAS-3D-MCP-bin` (~28 звёзд, Python+COM),
  `Alexey-Izilianov/kompas-mcp` (C#, v22), `xomyachok-shaolin/kompas-3d-mcp-linux`,
  `hymaxo/kompas3d-mcp`, `kostia-egik/geomwright`, `kuzadmin-coder/mcp-kompas-3D`,
  наш объект аудита `quja/kompas-3d-ai-bridge`.

**Практическое следствие для волны 2:** ждать официальный MCP не нужно, но и
изобретать API не нужно. Приоритеты подтверждаются — сопряжения через
`IMateConstraint`, чертёж и штамп, спецификация, экспорт STEP с проверкой импортом.

**Замечание по панели вайбкодинга:** рабочая папка `KOMPAS-3D MCP` панели не
известна (нет `.vibe/` и `AGENTS.md`), `vibe lease` возвращает «Проект не найден».
Аренда для этого проекта сейчас неприменима.

- `docs/WAVE3_CHANGES.md`.

**Проверка:** 42 + 39 + 41 тест, `test_mcp_stdio` (40 инструментов),
`test_mcp_bridge_routing`, compileall — всё зелёное и в рабочей копии, и в
чистой копии с тремя патчами подряд. Смоук: `tools/list -> 40`.

**Ключевые решения:**
- Сторож диалогов **не использует COM**: если КОМПАС висит на модальном окне,
  Automation повиснет на том же окне. Процесс ищется через `tasklist`, окна —
  через `EnumWindows` с фильтром по классу `#32770`.
- Политика: `close` только для информационных окон; вопросы, сохранение, выбор
  файла, ошибки и **неизвестные окна** — `report` (не закрываются). `apply`
  по умолчанию `false`, лимит 3 закрытия за вызов.
- Матрица версий: пустая матрица = «не проверено», а не «запрещено», поэтому
  поведение существующей установки не меняется. Версия запрашивается у COM
  только для действий из `guarded_actions` (проверено счётчиком обращений).
- Тесты-«стоп-краны» с числом инструментов обновлены в `test_wave1.py` (40) и
  `test_wave2.py` (40) осознанно.

**Урок:** базу для диффа следующей волны надо проверять по факту (число
инструментов, отсутствие новых модулей), иначе патч незаметно перепишет

**Найденный баг (важный):** `_attr(obj, name)` делал

**ни один** метод экспорта и **ни один** метод создания сопряжений — обе
фичи молча деградировали в «интерфейс недоступен». Исправлено в
`export_tools.py` и `mate_tools.py` (возвращается сам callable, аргументы
пробует вызывающий). Занесено в скилл `mcp-server-hardening-pass`.

инструментов), `test_mcp_bridge_routing`, compileall — зелёные в рабочей и
в чистой копии. Смоук: `tools/list -> 46`.

**Ключевые решения:**
- **Мост не называет ячейки основной надписи.** Нумерация зависит от стиля
  ОН в шаблоне; выдуманный словарь дал бы правдоподобно неверную запись.
  Инструмент работает номерами, без аргументов читает первые 60 ячеек.
- **Запись штампа использует контрольные точки волны 4**: снимок → запись →
  чтение обратно → Save → Close → Reopen → чтение снова; расхождение — откат
  из снимка, в ошибке указан id и `rolled_back`. Первая мутирующая операция
  с настоящим откатом, а не только с обнаружением.
- **Отказ для 3D-документа явный** (`no_layout_sheets` + тип документа), а не
  пустой список листов.
- **Спецификация помечена как производная**: `Standard` → стандартные
  изделия, `IsBillet` → материалы, есть дети → сборочная единица, иначе
  деталь. Настоящий `.spw` не читается — объектная модель не проверена ни на
  одной установке. Перекрёстная проверка: производное количество обязано
  совпасть с `eligible_occurrence_count`, иначе `cross_check.ok = false`.

**Находка:** унаследованный `src/capabilities.py` уже умел `sheet.info`,
`stamp.read`, `stamp.write`, но ни один инструмент каталога на них не
ссылался — через MCP они были недостижимы. Проверять надо не «реализовано
ли», а «есть ли маршрут из каталога».

**Ошибки сессии:** вставил в каталог строки с `\"` вне строкового литерала
(недопустимо в Python); `_views` падал на `import win32com` в COM-free среде
— теперь провал импорта считается «интерфейс не подтверждён»; порядок имён в
`VERSION.json` разошёлся с каталогом (тест сравнивает порядок, а не множество).

**Осталось после волны 5:** создание видов, размеров и объектов оформления;

  каждого мутирующего инструмента каталога — иначе предпросмотр молча
  проверит только схему и отрапортует «готово». Обратный тест ловит
  устаревшие записи.
- **Три вердикта**: `blocked` / `ready_with_unknowns` / `ready`. То, что
  требует COM, уходит в `unverifiable`, а не угадывается.
- **Без переданной версии защищённое действие = `unknown`**, не `fail`:
  поднимать «заблокировано» значило бы утверждать, что мост знает версию
  running-КОМПАСа.
- Тест сверяет байтовый хэш файла и список файлов рабочего каталога до и
  после предпросмотра: ничего не пишется.

**Попутно:** у `kompas_open_copy` не было `annotations` — добавил; теперь тест
`test_every_tool_has_annotations` требует их у всех инструментов.

**Ошибки сессии:** `Settings.work_dir` — это свойство, а не метод

### Продолжение: ТЗ на щитовой доменный слой (`shity_domain_layer_spec.html`)

Скачал и разобрал исходники обоих эталонов (codeload + tar, `git clone` не нужен):

- **qty разворачивается.** «Автомат 40 А, qty 3» — три автомата. Без этого
  `BUSBAR_OVERLOAD` не срабатывал — найдено тестом, а не чтением кода.
- Переворот координат только в `to_cad()`.
- `error` — структурно невозможно, `warning` — разрешено, но показать (из CLG2).

**Ошибки сессии (три):**
1. В тестах перепутал хелпер `layout_of()` с точкой входа `check_layout()`.

## Волна 8 — раскладка как генератор координат

**Поверхность 49 → 50.** Новый инструмент `kompas_cabinet_layout_build`
(readOnlyHint true), действие `cabinet.layout_build`.

**Файлы:** `src/cabinet_build.py` (новый, 348 строк), правки `cabinet_tools.py`,
`engineering_capabilities.py`, `mcp/tools_catalog.py`, `VERSION.json`,
`tests/test_wave8.py` (38 тестов), `docs/WAVE8_CHANGES.md`. Патч `wave8.patch` —
55 КБ, 14 файлов; проверен на чистой копии (pristine + wave1..7), 311 тестов.

**Модель входа:** `plate` / `library` / `lines` / `rail` / `defaults` / `ducts`.
Выход: `layout` (совместим с `check_layout`), `rows`, `unplaced`, `self_check`,
`ducts_generated`.

**Ключевое решение — DIN-рейка.** `rail_offset_mm` = расстояние от ВЕРХНЕЙ кромки
детали до оси рейки. Все детали ряда удовлетворяют `y + rail_offset = rail_y`.
Если поля нет — центр по высоте (соглашение, не расчёт). Без этого клеммы (h=40)
и автоматы (h=90) стоят «лесенкой».

**Партия → сет, а не N элементов.** `qty: 24` — один `group` с `count`,
`tag_start`, `tag_step`. Это то, что делает волну 9 дешёвой: одна позиция состава
= один вызов `component_pattern_linear`, а не 24 вставки.

**5 причин unplaced** (ни одна не подменяется оценкой): `unknown_lib_key`,
`unconfirmed_size` (нулевой габарит или флаг `confirm`), `zero_width`,
`wider_than_plate`, `no_vertical_space`. Тест требует, чтобы ни одна запись из
`unplaced` не попала в геометрию.

**Генератор обязан прогонять свой вывод через `check_layout`** — иначе
«сгенерировано» и «корректно» расходятся (две правды для инженера).

### Дефект (главный)

`usable_span` искала правую границу как `min(x)` по всем вертикальным каналам —
левый канал (x=0) и есть этот минимум, поэтому `x1` уходил в минус, доступная
ширина становилась нулевой и ВСЕ позиции падали в `wider_than_plate`. Поймано не
чтением кода, а живым прогоном. Исправлено разведением ролей: границу задают
только каналы, примыкающие к кромке (допуск 1 мм); канал в середине поля —
препятствие, его ловит `check_layout`, а не `usable_span`. Регрессия закреплена
тестом `test_usable_span_does_not_collapse_on_middle_duct`.

**Урок:** смешивать «граница области» и «препятствие внутри области» в одном
проходе нельзя — схлопывает область в ноль. Разводить по признаку примыкания.

### Прочие правки

- Три теста упали на АРИФМЕТИКЕ ФИКСТУРЫ: задал панель 300 мм, забыв, что
  `clearance_equipment_to_duct_mm` по умолчанию 20 мм с каждой стороны — доступно
  260 при требуемых 241, переноса нет. Считать доступную ширину, а не габарит.
- Имена `test_tool_count_is_42` (wave2/3/4, ожидание 50) и `..._is_49` (wave5/6)
  приведены к реальности.
- Стоп-краны 49 → 50 во всех wave1..7, `VERSION.json` — и счётчик, и список
  `mcp_tools` (тест `test_version_json_matches_catalog` сравнивает порядок имён).

## Волна 9 — материализация раскладки (план + исполнение)

**Поверхность 50 → 52.** `kompas_cabinet_materialize_plan` (readOnly) и
`kompas_cabinet_materialize_apply` (мутирующий, требует явный `apply: true`).

**Файлы:** `src/cabinet_materialize.py` (план, чистый), `src/cabinet_exec.py`
(исполнитель, COM лениво), правки `cabinet_tools.py`,
`engineering_capabilities.py`, `dryrun.py` (PREFLIGHT для apply),
`tools_catalog.py`, `VERSION.json`; `tests/test_wave9.py` (50 тестов);
`docs/WAVE9_CHANGES.md`, `docs/STEP_IMPORT_PIPELINE.md`.

**Патч `wave9.patch` — 85 КБ, 18 файлов**, проверен на чистой копии
pristine+wave1..8: 361 тест зелёный, `test_mcp_stdio 52`.

### Модель плана

Стадии: `checkpoint → body → insert → place → pattern → mark → verify`.
Шаг = `{seq, stage, tool, action, params, why, critical, automated}`.

- **Символические ссылки**: селектор = `{"from_step": N, "field":
  "component_index"}`. Числовой индекс экземпляра известен только КОМПАСу
  после вставки. `component_index()` берёт `result.readback.component_count - 1`
  (**подтверждено только чтением кода** — проверить на живом КОМПАСе).
- **Разбиение сетов**: `pattern_linear` count 2..20 → 24 клеммы = `[12,12]`,
  каждая часть insert+place+pattern, вторая и далее с `allow_duplicate=True`.
- **Тело один раз на используемый ключ** (не на позицию и не на всю библиотеку).
- **Два источника геометрии**: `primitive` (блок по габариту) и `fragment`
  (готовый .m3d по `fragment_ref`). План от вида не зависит — задел под
  библиотеку фрагментов.
- **`automated: false`** у checkpoint и verify: у них контракт `bridge_root`/`root`,
  не `session` → попадают в `deferred`, исполнитель их не трогает.
- Маркируется только первый экземпляр сета (остальные индексов не имеют).

### Дефекты (4 в коде, 2 в моих тестах)

1. **Ссылки указывали не туда**: `seq - 1` между insert и place давал
   **создание тела**, а не вставку. Поймано живым прогоном с проверкой «каждая
   ссылка → `assembly.insert_component`». Теперь номер вставки в переменной.
2. **Исполнитель вызывал шаг с `selector=None`**: `component_index` вернул None →
   подстановка вернула None → вызов с пустым селектором. Теперь None = «индекс
   неизвестен» → `skipped`.
3. **Шаги вставки без имени сборки**: создавался insert с пустым
   `assembly_filename`. Теперь без сборки размещение не планируется (тела —
   можно).
4. **Тела на всю библиотеку**: библиотека — справочник, а не состав. Только
   используемые ключи.
5. Тест `no_assembly` ожидал «шагов нет вообще» — неверно.
6. Тест `non_critical_failure` ожидал 1 ошибку маркировки — позиций две.

**Дальше:** волна 10 — сверка BOM со спецификацией + чтение настоящего `.spw`;
конвейер STEP → `.m3d` (план в `docs/STEP_IMPORT_PIPELINE.md`) после приёмки

## Волна 10 — сверка состава щита с перечнем КОМПАС

**Поверхность 52 → 53.** `kompas_cabinet_bom_reconcile` (readOnly). Модуль
`src/cabinet_reconcile.py` — чистый, **не читает КОМПАС**, принимает готовый
результат `kompas_bom_read` и сверяет с моделью раскладки.

**Патч `wave10.patch` — 47 КБ, 16 файлов**, проверен на чистой копии
pristine+wave1..9: 395 тестов зелёные, `test_mcp_stdio 53`.

### Ключевое решение

**Сверка по имени файла детали (`source_file`), а не по позиционному
обозначению.** В волне 9 маркируется только исходный экземпляр сета → у 24
клемм в перечне одно обозначение `B101`. Сверка по обозначениям дала бы 23
ложных расхождения на одном сете. Обозначения — вторичная проверка, расхождение
по ней помечается причиной, а не ошибкой сборки.

`marking_policy`: `first_only` (по умолчанию, от сета ждём одно обозначение) |
`all` (полная серия B101..B124). Регистр имён файлов не важен (casefold).

**Отчёт:** `matched` / `missing_in_bom` / `quantity_mismatch` (с `delta`) /
`unexpected_in_bom` / `designation_gaps` / `unverified`. Вердикты `match`,
`mismatch`, `match_with_unknowns`.

**Имя файла выводится правилом `cabinet_materialize.part_filename(lib_key)`**, а
не требуется в библиотеке: генератор раскладки (`cabinet_build.load_build`)
вообще не сохраняет поле `filename`. Без этого вывода все позиции уходили в
`unverified` — поймано живым прогоном до написания тестов.

### Дефекты

1. **`designation_series` инвертировала полноту серии**: возвращала
   `len(series) < count`, из-за чего серия из одного `QF` при запросе трёх
   помечалась полной. Теперь «не удалось нарастить» → `False` → `unverified`.
2. Три неверных ожидания в тестах: причина gap проверялась при политике `all`
   (актуальна при `first_only`); `match_with_unknowns` проверялся на пустом
   перечне (там `mismatch`); явное `filename` проверялось через генератор
   раскладки, который его отбрасывает.

**Дальше:** конвейер STEP → `.m3d` (после приёмки, на машине с КОМПАС);
библиотека фрагментов (opensource-аналога нет).

Роман спросил перед волной 9. Прогнал 27 запросов (`research/gh_search4.py`,

**Альтернатива (не GitHub, не opensource):** производители дают STEP бесплатно —
ABB через PARTcommunity (CADENAS), Schneider через BIMobject, Legrand через
TraceParts. Лицензия «для проектирования», перераспространение в составе
продукта запрещено.

импортирует IGES, STEP, JT, STL, Parasolid, OBJ, ACIS, CD3 (help.ascon.ru) —
формат не проблема, проблема в отсутствии конвейера, а отладить его без КОМПАС
нельзя.

**Решение Романа:** план + габаритные блоки. Проектировать волну 9 так, чтобы
источник геометрии был двух видов — `primitive` (габаритный блок через
`kompas_part_add_primitive`) и `fragment` (готовый `.m3d` по `fragment_ref`) —
а план материализации от вида источника не зависел.

## Волна 11 — электрорасчёт щита (`cabinet_calc`)

`src/cabinet_calc.py` + `kompas_cabinet_calc`, поверхность 53→54, 455 тестов
(60 новых), `wave11.patch` (94 КБ, 17 файлов) проверен на чистой копии
pristine+wave1..10.

**Главное: нормативных таблиц внутри модуля нет.** Допустимые токи, каталог
аппаратов, коэффициенты спроса и время-токовые характеристики приносит caller
в `tables` с полем `source`; источник возвращается в `provenance`. Отказ вместо
экстраполяции: нет таблицы → `refusals`, нет данных для критерия →
`not_checked` (а не «прошло»), ток вне характеристики → `selective: null`.
`verdict`: computed / computed_with_gaps / refused.

Без таблиц считается физика: `current`, `voltage_drop`, `fault_current`,
`derating`. С таблицами: `max_demand`, `cable_size`, `breaker_select`,
`selectivity`. Удельное сопротивление — свойство металла (медь 0.01754,
алюминий 0.02899 Ом·мм²/м), поправки на температуру/прокладку вносит caller.

**Дефект:** `load_current` распаковывал результат `calc_current` как кортеж —
любой расчёт сечения по мощности падал с ValueError. Поймано тестом.

Однофазная петля «фаза-нуль» без сопротивления нулевой последовательности не
считается (не оценка, а отказ).

## Волна 12 — каталог оборудования и поиск по документам

Два инструмента из пробелов таблицы сравнения: `kompas_cabinet_catalog_search`
(подбор АВ/УЗО/контакторов/клемм/шин по параметрам — то, что заявляет
`sans-calc-mcp`) и `kompas_docs_search` (поиск по документам с цитатой
файл+строка — то, что делает `SwitchScope`). Поверхность 54→56, 493 теста
(38 новых), `wave12.patch` (139 КБ, 20 файлов) проверен на чистой копии
pristine+wave1..11.

**Замкнута цепочка подбор → габарит → раскладка → расчёт.** Каждая позиция
каталога возвращается с полем `layout` (width_mm/height_mm/rail_offset_mm),
пригодным прямо для `cabinet_layout_build`; тест проверяет, что габарит доходит
до координат (`y + rail_offset = ось рейки`).

**Данных в модуле нет** — каталог приносит caller (`catalog` или `catalog_path`
внутри корня проекта). В репозитории только
`data/cabinet_catalog.example.json`: 142 позиции на типовых модульных габаритах
DIN 43880, **без производителей, серий и артикулов**, `example: true` → ответ
тоже помечается. Позиция без габарита → `unverified`, не типовой размер.

`docs_search` — полнотекстовый, не семантический: все слова запроса должны
встретиться в строке; чтение только внутри корня проекта/cwd; предел файлов
сообщается через `truncated`.

Ближайшее, что осталось от конкурентов: STEP → `.m3d` (заблокировано машиной
с КОМПАС) и файл лицензии.

## Пример каталога заменён на реальные данные IEK (просьба Романа)

`data/cabinet_catalog.example.json` — **100 реальных позиций** с открытых
карточек `www.iek.ru` (2026-09-20): 79 АВ KARAT ВА47-29 (1P–4P, B/C/D, 1–63 А,
4,5 кА), 19 УЗО ВД1-63 тип А (10/30/100 мА), 1 контактор ARMAT KMR. У каждой —
артикул, серия, URL, source. Снималось через curl + разбор JSON в разметке
(WebFetch на карточки УЗО отдаёт «loading», поэтому парсили HTML напрямую).

**Два вывода, из-за которых синтетическая заглушка была вредной:**

1. **Реальный модуль IEK — 18 мм, не 17,5.** Ширина 18/36/54/72 мм, подтверждено
   дважды: габарит инд. упаковки + число модульных расстояний. УЗО шире: 2P 42 мм,
   4P 77 мм (шаг не кратен — «модуль × полюса» не работает). На плите 600 мм в ряд
   входит **26** автоматов 1P, заглушка обещала **27** — лишний фантомный слот.
2. **Подбор по току КЗ отказывает там, где «на глаз» подходило.** Трансформатор
   630 кВА, uк 5,5 % → 17,4 кА на вводе, а ВА47-29 держит 4,5 кА → `selected: null`.
   С линией 40 м × 4 мм² ток 1,17 кА → находится MVA20-3-040-C.

Оставлено пустым честно: `rail_offset_mm` (производитель не публикует) и габарит
контактора KMR (карточка: «2 модуля» против 50 мм в упаковке — расхождение не
разрешено домыслом).

Патч `wave12.patch` пересобран (177 КБ, 20 файлов), 501 тест зелёный.
