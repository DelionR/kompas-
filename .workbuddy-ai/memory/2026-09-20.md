## Сверка остатков: что из функций конкурентов ещё не реализовано

Вопрос Романа после волны 12. Сверил актуальное состояние моста (56
инструментов, 501 тест) с таблицей `mcp_servers_comparison.md` и актуализировал
её: закрытые пункты помечены, остатки пересортированы по цене и отдаче.

**Закрыто волнами 11–12 (три пробела из шести):** электрорасчёты
(`cabinet_calc`), подбор по каталогу (`cabinet_catalog_search` + 100 реальных
позиций IEK), поиск по документам с цитатами (`kompas_docs_search`).

**Осталось, без КОМПАСа реализуемо:**
1. Нормативные таблицы как данные — главный остаток. Движок считает, таблиц в
   репозитории нет ни одной. Легальный и готовый источник: таблицы
   селективности IEK в XLSX → данные для `trip_curves`. Таблицы ПУЭ брать из
   официального источника, из памяти перепечатывать нельзя.
2. Спецификация и маркировка из раскладки (`labels` сейчас пустое).
3. Однолинейная схема как данные.
4. Семантика в поиске по документам (сейчас подстрока).

**Заблокировано машиной с КОМПАСом:** STEP → `.m3d`, запись спецификации и
шильд в документ, приёмка.

**Брать не стоит:** каталоги и 3D-модели производителей в продукте (лицензии),
расчёт сети через OpenDSS, средневольтные КРУ, привязка к чужим САПР.

**Отдельный пробел уровня протокола: в мосте нет MCP-ресурсов вовсе** — ни
норм, ни справочников, только инструменты.

**Блокер не функциональный:** файл лицензии в репозитории отсутствует.

## Уточнение: MCP-сервер для ECAD-системы существует (EPLAN)

Вопрос Романа: «у eplan mcp есть еще что-то из преимуществ?». Проверил GitHub
API по `eplan mcp`: `covagashi/eplan-rag-mcp` (96 ★, MIT, обновлялся недавно),
`paulinholt/eplan-mcp-bridge`, `swater-kankyo/eplan-mcp-oss`,
`binfen1/Eplan_2026_IA_MCP_scripts`.

**Масштаб `eplan-rag-mcp`:** 199 инструментов (или 13 в режиме discovery):
183 типизированных `eplan_*`-действия, 4 инструмента каталога, открывающие
~1 050 GUI-действий из `MFTools.xml`, 8 служебных, 4 на AAS/AASX. Плюс живая
модель данных (страницы, устройства, обозначения соединений), чтение дерева
системных сообщений, полный беспилотный цикл (запуск/перезапуск EPLAN, подмена
DLL, черновые проекты из шаблона), приватные модули расширения, отдельный файл
`llm.md` для модели, три удалённых RAG на Cloudflare Workers по документации
EPLAN. README на трёх языках (англ/кит/рус).

**Вывод:** прямого конкурента нет — он автоматизирует *систему*, а не домен
(нет подбора, расчётов, компоновки). Но планка по глубине автоматизации САПР
задана, и предыдущая формулировка «ECAD-конкуренции нет» была неверна —
исправлена в `mcp_servers_comparison.md`.

**Что взяли из него как приём, а не как функцию** (новый раздел документа):
1. каталог действий вместо инструмента на действие (у нас уже так в
   `cabinet_calc` через `kind`);
2. режим discovery (13 вместо 199) — пригодится, когда наших станет много;
3. отдельный `llm.md` для модели — у нас документация волн написана для инженера;
4. документация вендора как RAG — `kompas_docs_search` уже умеет, нужно только
   положить документацию КОМПАС в доступный каталог.

**Новые остатки, добавленные в список:** №8 — диагностика через системные
сообщения (нужна машина; у нас есть `kompas_dialogs` и `artifact_check`, но не
чтение журнала КОМПАС); №9 — AAS/AASX как цифровой двойник (машина не нужна,
формат открытый; ценность только при обмене с заказчиком/PLM).

**Практический вывод для Романа:** из EPLAN-сервера ничего не переносим прямо —
он внутри экосистемы EPLAN и бесполезен без неё. Берём только приёмы.
