# 2026-09-22

## Разбор остатка «схема как модель данных» (без правки кода)

Роман спросил, что нужно, чтобы реализовать схему как модель данных. Проверил
два источника, оба результата нужны для будущей волны.

### ГОСТ 2.702-2011 найден и парсится

`https://files.stroyinf.ru/Data2/1/4293800/4293800211.htm` — HTML-двойник,
191 КБ, отдаётся без проблем. Тем же приёмом, что ГОСТ 50571.5.52 и 2.710-81.

Что стандарт нормирует и что пригодится:

- на схеме рядом с позиционным обозначением **в квадратных скобках указывают
  обозначения цепей**, в которых находится элемент;
- на последующих листах помещают **таблицы соединений** с графами «Адрес»
  (обозначение цепи и/или позиционное обозначение присоединяемых элементов),
  «Цепь» (характеристика цепи), «Адрес внешний»;
- номера контактов записывают **в порядке возрастания**;
- «на принципиальной схеме должны быть однозначно определены все элементы».

То есть стандарт даёт ровно то, чего у нас нет: адрес соединения, обозначение
цепи, таблицу соединений. Это не требует машины с КОМПАС.

### ETIM у автомата: полюса есть, распиновки нет

Карточка ВА47-29 1P C 1А (URL есть в `data/cabinet_catalog.example.json` у всех
100 позиций). В ETIM:

- `EF001391` Количество полюсов — 1;
- `EF003961` Тип подключения — «Винтовое соединение»;
- `EF000267` Макс сечение входящего кабеля — 25 мм²;
- `EF005548` Количество защищенных полюсов.

**Числа зажимов и распиновки (какой зажим вход, какой выход) в ETIM нет.**
Для модульных аппаратов число зажимов выводится из полюсов (2 × poles) — это
расчёт, его надо пометить `derived`. Для реле, счётчиков и ПЛК без паспорта
распиновку взять неоткуда → отказ.

### Главное ограничение, сформулированное для Романа

**Соединения нельзя вывести из раскладки.** Раскладка знает координаты, но не
электрические связи. Значит источник схемы — ввод инженера либо импорт из
чужого формата (EPLAN XML, или чтение документа КОМПАС — для этого нужна
машина с КОМПАС). Это и есть настоящий блокер, а не код.

### Что уже есть как фундамент

Перечень (`cabinet_spec.bom`), позиционные обозначения по ГОСТ 2.710-81, состав
и секционирование (`cabinet_domain`), каталог с полюсами и габаритами. Не
хватает: зажимов, цепей, таблицы соединений, проверок связности, кросс-ссылок
между листами.

## Волна 16 реализована: `src/cabinet_schematic.py`

Роман выбрал «Ввод + типовые цепи». Сделано, проверено, патч принят.

- Модель: устройства → зажимы → цепи → соединения. Шесть видов через
  `{"kind": build|terminals|nets|table|check|typical}`.
- **Графы таблицы соединений — цитата ГОСТ 2.702-2011**: «Конт.», «Адрес»,
  «Цепь», «Адрес внешний», контакты по возрастанию. В `columns_source` и
  `provenance`.
- **Нумерации цепей в ГОСТ 2.702-2011 нет** — проверено: слово «маркировка» в
  тексте не встречается. Обозначение цепи приносит caller, шаблонное помечается
  `derived`.
- Число зажимов = `2 × poles`, `derived`. Нет полюсов → `no_terminals`, а не
  догадка.
- 7 проверок: `no_designation`, `duplicate_designation`, `unknown_device`,
  `open_net`, `unknown_net`, `unconnected_device`, `unprotected_net`.
  Тонкость: **цепь с `external_address` не считается разомкнутой** — иначе ввод
  всегда давал бы ложное срабатывание.
- `kind=typical` (ввод → аппарат → группа) сам себя проверяет теми же
  правилами, 0 ошибок, и его вывод подаётся обратно в `kind=build`.

Новый инструмент `kompas_cabinet_schematic`, действие `cabinet.schematic`.
Поверхность **58 → 59**. Тесты 603 → **645** (42 новых). Патч
`wave16.patch`, 19 файлов, принят на чистой копии.

### Ловушки, на которых потерял время

- `protocol.ok(action, result)` отдаёт только `{"ok": True, "result": …}` — поля
  `action` в ответе нет. Проверять маршрут надо через `ACTION_MAP`, а действие —
  через сам адаптер.
- `VERSION.json` и `tools_catalog` обязаны совпадать **по порядку имён**, не
  только по множеству: гейт `test_version_json_matches_catalog` сравнивает
  списки. Имя вставлять туда же, куда встал инструмент в каталоге.
- `engineering_capabilities` не импортируется без PIL (`screenshot`), в тестах
  проверить диспетчер через него нельзя — только через `cabinet_tools`.
- `git.exe` не видит `/tmp` Git Bash. Патч собирать по абсолютному
  Windows-пути: `git diff --no-index --src-prefix=a/ --dst-prefix=b/
  "C:/Users/admin/AppData/Local/Temp/base16" "kompas-3d-ai-bridge-main"`.
