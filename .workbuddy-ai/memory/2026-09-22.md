# 2026-09-22

## Разбор остатка «схема как модель данных» (без правки кода)

Роман спросил, что нужно, чтобы реализовать схему как модель данных. Проверил
два источника, оба результата нужны для будущей волны.

### ГОСТ 2.702-2011 найден и парсится

`https://files.stroyinf.ru/Data2/1/4293800/4293800211.htm` — HTML-двойник,
191 КБ, отдаётся без проблем. Тем же приёмом, что ГОСТ 50571.5.52 и 2.710-81.

Что стандарт нормирует и что пригодится:

- на схеме рядом с позиционным обозначением **в квадратных скобках указывают
  обозначения цепей**, в которых находится элемент;
- на последующих листах помещают **таблицы соединений** с графами «Адрес»
  (обозначение цепи и/или позиционное обозначение присоединяемых элементов),
  «Цепь» (характеристика цепи), «Адрес внешний»;
- номера контактов записывают **в порядке возрастания**;
- «на принципиальной схеме должны быть однозначно определены все элементы».

То есть стандарт даёт ровно то, чего у нас нет: адрес соединения, обозначение
цепи, таблицу соединений. Это не требует машины с КОМПАС.

### ETIM у автомата: полюса есть, распиновки нет

Карточка ВА47-29 1P C 1А (URL есть в `data/cabinet_catalog.example.json` у всех
100 позиций). В ETIM:

- `EF001391` Количество полюсов — 1;
- `EF003961` Тип подключения — «Винтовое соединение»;
- `EF000267` Макс сечение входящего кабеля — 25 мм²;
- `EF005548` Количество защищенных полюсов.

**Числа зажимов и распиновки (какой зажим вход, какой выход) в ETIM нет.**
Для модульных аппаратов число зажимов выводится из полюсов (2 × poles) — это
расчёт, его надо пометить `derived`. Для реле, счётчиков и ПЛК без паспорта
распиновку взять неоткуда → отказ.

### Главное ограничение, сформулированное для Романа

**Соединения нельзя вывести из раскладки.** Раскладка знает координаты, но не
электрические связи. Значит источник схемы — ввод инженера либо импорт из
чужого формата (EPLAN XML, или чтение документа КОМПАС — для этого нужна
машина с КОМПАС). Это и есть настоящий блокер, а не код.

### Что уже есть как фундамент

Перечень (`cabinet_spec.bom`), позиционные обозначения по ГОСТ 2.710-81, состав
и секционирование (`cabinet_domain`), каталог с полюсами и габаритами. Не
хватает: зажимов, цепей, таблицы соединений, проверок связности, кросс-ссылок
между листами.

## Волна 16 реализована: `src/cabinet_schematic.py`

Роман выбрал «Ввод + типовые цепи». Сделано, проверено, патч принят.

- Модель: устройства → зажимы → цепи → соединения. Шесть видов через
  `{"kind": build|terminals|nets|table|check|typical}`.
- **Графы таблицы соединений — цитата ГОСТ 2.702-2011**: «Конт.», «Адрес»,
  «Цепь», «Адрес внешний», контакты по возрастанию. В `columns_source` и
  `provenance`.
- **Нумерации цепей в ГОСТ 2.702-2011 нет** — проверено: слово «маркировка» в
  тексте не встречается. Обозначение цепи приносит caller, шаблонное помечается
  `derived`.
- Число зажимов = `2 × poles`, `derived`. Нет полюсов → `no_terminals`, а не
  догадка.
- 7 проверок: `no_designation`, `duplicate_designation`, `unknown_device`,
  `open_net`, `unknown_net`, `unconnected_device`, `unprotected_net`.
  Тонкость: **цепь с `external_address` не считается разомкнутой** — иначе ввод
  всегда давал бы ложное срабатывание.
- `kind=typical` (ввод → аппарат → группа) сам себя проверяет теми же
  правилами, 0 ошибок, и его вывод подаётся обратно в `kind=build`.

Новый инструмент `kompas_cabinet_schematic`, действие `cabinet.schematic`.
Поверхность **58 → 59**. Тесты 603 → **645** (42 новых). Патч
`wave16.patch`, 19 файлов, принят на чистой копии.

### Ловушки, на которых потерял время

- `protocol.ok(action, result)` отдаёт только `{"ok": True, "result": …}` — поля
  `action` в ответе нет. Проверять маршрут надо через `ACTION_MAP`, а действие —
  через сам адаптер.
- `VERSION.json` и `tools_catalog` обязаны совпадать **по порядку имён**, не
  только по множеству: гейт `test_version_json_matches_catalog` сравнивает
  списки. Имя вставлять туда же, куда встал инструмент в каталоге.
- `engineering_capabilities` не импортируется без PIL (`screenshot`), в тестах
  проверить диспетчер через него нельзя — только через `cabinet_tools`.
- `git.exe` не видит `/tmp` Git Bash. Патч собирать по абсолютному
  Windows-пути: `git diff --no-index --src-prefix=a/ --dst-prefix=b/
  "C:/Users/admin/AppData/Local/Temp/base16" "kompas-3d-ai-bridge-main"`.

## Вопрос: заработает ли на КОМПАС v16 под Windows 7

Ответ — нет, и границы проверены, а не предположены:

- **Python: потолок 3.8.10.** Официальная страница python.org/downloads/windows
  прямо пишет для каждой 3.9+: «cannot be used on Windows 7 or earlier». У 3.8.10
  ограничение только «XP or earlier». Мост требует 3.11 (`py.exe -3.11`).
- **COM: мост цепляется к `KOMPAS.Application.7`** (`src/kompas_session.py`,
  `GetActiveObject`, 8 попыток) и отдельно к
  `KOMPAS.Application.5` для видовых операций. Если `.7` не зарегистрирован —
  отказ `kompas_active_instance_not_found`. Есть ли `.7` в v16, **не подтверждено**:
  поиск по SDK АСКОН не дал номера версии, с которой доступен API7. Проверка на
  машине: `reg query "HKEY_CLASSES_ROOT\KOMPAS.Application.7"`.
- **Щитовой домен работает без КОМПАС и без pywin32**: `src/cabinet_*.py` и
  `src/normative*.py` не импортируют `win32com`, а 645 тестов зелёные на машине,
  где pywin32 не установлен. То есть на Win7 мост годится как расчётный стенд.
- Код почти совместим с 3.8: единственное `list[...]` — аннотация локальной
  переменной в `src/errors.py:203`, она не вычисляется в runtime.

## Где брать базы оборудования, кроме IEK (проверено запросами)

**Главная находка, переворачивающая план: нагрев НКУ разблокирован.**

ETIM-класс EC000042 (модульный автомат) содержит признак **«Потери энергии»
`EF005387`, Вт**. Проверено на живой карточке IEK ВА47-29 1P C 1А:
`{"id":"EF005387","name":"Потери энергии","unit":"Вт","value":"3.0"}`. То есть
мощность рассеивания производитель **публикует**, мы её просто не собирали.
Там же **«Монтажная глубина - ниши» `EF000218` = 73,6 мм** — закрывает остаток
волны 15 про глубину под оборудование. На карточке всего 43 ETIM-признака.

Значит остаток №1 («нагрев НКУ — данных нет») опирался на неверную
предпосылку. Нужно добавить EF005387 и EF000218 в FEATURES добытчика и
пересобрать каталог. Справочник признаков — бесплатный
`viewer.etim-international.com` (classes EC000042 и др.).

### Статус источников по брендам (проверено curl на своих страницах)

- **EKF — кандидат №1**: отдельный портал `https://etim.ekfgroup.com/` («ETIM
  каталог»), плюс JSON API `https://api.ekfgroup.com/`. Тот же приём, что с IEK.
- **TDM Electric**: ETIM нет, только `ld+json` — данных для чистого парсинга нет.
- **Dekraft**: ни ETIM, ни API — только грязный разбор HTML.
- **КЭАЗ**: единичные упоминания, ETIM-идентификаторов нет.
- **EPLAN Data Portal**: 550+ производителей, 2,3 млн компонентов — крупнейшая
  база, но бесплатно **только при действующей подписке EPLAN** («Free to use
  with current Eplan license subscription and Eplan ID»). У нас лицензии нет —
  источник закрыт.
- **ETIM International**: стандарт открытый, классификатор скачивается (у ETIM
  North America — ZIP с IXF). Это классы и признаки, **не изделия**.
- **elec.ru**: агрегатор каталогов, файлов и прайсов по брендам — как источник
  PDF и прайсов, не структурированных данных.

### Ограничение, которое остаётся

Каталоги производителей в продукт включать нельзя (лицензия «для
проектирования»). У нас так и сделано: `example: true` в JSON, источник в

## Мультибренд: что в системе готово, что сломается (проверено по коду)

**Готово к смешиванию брендов:**
- `manufacturer` есть в данных и в выдаче поиска; фильтр по `manufacturer` и
  `series` уже работает (`cabinet_catalog.matches`).
- **per-item `source`**: `"source": item.get("source") or meta.get("source")` —
  у каждой позиции свой источник, значит provenance при смешанном каталоге
  остаётся честной. В 100 позициях IEK source заполнен у всех.
- Раскладка (`item_to_layout`) берёт `width_mm`/`height_mm`/`depth_mm` из
  позиции, а не из модулей — **бренд-независима**, смесь считается верно.
- Потери мощности (Вт) суммируются по всем брендам — величина универсальная.

**Сломается:**
- `src/cabinet_enclosure.py`: `MODULE_WIDTH_MM = 18.0` — **глобальная
  константа**. Бренд с шагом 17,5 мм даст неверную ширину ряда
  (`modules / rows × 18`) и неверный подбор корпуса по модулям. Нужно поле
  `module_width_mm` на позицию/бренд с отказом, если его нет.
- Один `catalog_path` — списка путей нет. Мультибренд сейчас только через один
  общий файл (или inline-массив `catalog`).
- `lib_key` = `id` позиции — при смешивании возможна коллизия артикулов.
- **Аксессуаров в модели нет**: шинные гребёнки, шины N/PE бренд-зависимы —
  гребёнка одного бренда физически не встанет на автоматы другого. Держит
  инженер, система не проверяет.
- Селективность кросс-бренд требует паспортных ВТХ; их нет → `selective: null`.
