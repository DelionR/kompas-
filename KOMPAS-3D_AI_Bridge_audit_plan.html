01Что это за проект сегодня

Это не обычный MCP-сервер и не набор обёрток над API. Это детерминированный исполнительный слой, который физически отделяет «вероятностный» ИИ от «строгого» COM-интерфейса КОМПАС-3D. Идея архитектуры:

AI / LLM / кодирующий агент
        │  MCP (stdio, JSON-RPC, самописный)
        ▼
MCP-сервер ── пишет JSON-файлы в runtime/commands
        │     и опрашивает runtime/responses каждые 80 мс
        ▼
Python-воркер (единственный, кто трогает COM, живёт в интерактивной сессии Windows)
        ▼
KOMPAS COM / API7 (+ API5 для видов)
        ▼
КОМПАС-3D v25 x64

Ключевое решение: MCP-процесс никогда не обращается к COM напрямую. Он только кладёт структурированный запрос в файл. Воркер — отдельный процесс с heartbeat — читает файл и исполняет действие в той же пользовательской сессии, где открыт КОМПАС. Это позволяет агенту работать даже из песочницы, не имеющей доступа к COM.

02Что уже сделано хорошо (и что нельзя ломать при рефакторинге)

У проекта есть несколько решений, которых нет у большинства публичных MCP для САПР. Их надо сохранить:

1. Доказательная запись, а не «команда улетела». Каждый мутирующий инструмент делает байтовый снапшот → проверку точного активного PathName до записи → Save → Close → Reopen → повторное чтение → и только потом объявляет успех. В worker.py даже есть отдельный защитный модуль KOMPAS_SAFE_REOPEN_TARGET_FIX_1_1_12B, который запрещает reopen «куда-нибудь» и разрешает открыть только ровно тот файл, который был закрыт.
2. Отказ запускать второй КОМПАС. KompasSession.connect() делает до 8 попыток GetActiveObject("KOMPAS.Application.7") и при неудаче падает с диагностикой — вместо того чтобы через Dispatch поднять скрытый второй экземпляр и дальше работать не с той моделью. Для САПР это критично и реализовано лучше, чем у многих.
3. Честность инженерных данных. В skills/kompas-engineering/SKILL.md прямым текстом: никогда не выдумывать материал, плотность, массу, толщину, допуск, координаты. Инструменты это поддерживают: kompas_material_set требует, чтобы материал и плотность совпадали с отдельно прочитанным эталонным .m3d, иначе отказ. А kompas_part_add_hole в описании прямо пишет: «native IHole3D feature is not claimed» — то есть не выдаёт вырез за «отверстие по ГОСТ».
4. Двухканальная верификация. API-данные и свежий скриншот вьюпорта, причём в SKILL.md зафиксировано: «красивый скриншот не доказывает инженерную корректность, а API PASS не доказывает визуальную корректность». Скриншот возвращается прямо в ответе MCP как image/png, то есть модель смотрит на текущее состояние, а не на устаревший файл.
5. Гигиена записи. Работа только на копиях *_AGENT_COPY, защищённые корни источников, allow-list каталога jobs/, лимит 300 с, отказ при упоминании защищённых путей, восстановление ранее активного документа после операции.

03Проблемы, найденные в коде

Ниже — только то, что подтверждается чтением файлов, с указанием места. Разбито по приоритету влияния на работоспособность.

Уровень P0 — мешает работать уже сейчас

P0Конфиг не подключён: политика безопасности захардкожена

В src/config.py есть функция load_config(), которая читает config/agent_config.json — но она не вызывается нигде в проекте. При этом src/safety.py жёстко прошивает пути C:\KOMPAS_AI_WORKSPACE\00_SOURCE, ...\90_OUTPUT и т. д., игнорируя те же самые ключи в конфиге.

Следствие: файл agent_config.example.json — декорация. Перенос проекта на другую машину или смену структуры каталогов придётся делать правкой исходников. Ключи protected_roots / write_roots / viewport.crop / view.projection_indices не имеют эффекта.

src/config.py:6-11 → load_config(root) определена grep "agent_config" → единственные вызовы в tests/build_cap2_golden.py src/safety.py:5-8,18 → Path(r"C:\KOMPAS_AI_WORKSPACE\00_SOURCE") и т.д.
P0Расход контекста модели не ограничен

kompas_component_topology по умолчанию может вернуть до 5000 граней, 10 000 рёбер и 10 000 вершин; kompas_model_tree — дерево до глубины 12; kompas_pmi_read — до 2000 размеров. Всё это сериализуется с indent=2 и целиком уходит в контекст модели.

Следствие: одна операция «посмотреть топологию сборки» способна съесть контекстное окно и после этого агент начинает «забывать» задачу. Именно эту проблему параллельный проект KOMPAS-3D MCP решает явно: «большие результаты складываются в runtime memory/resources/artifacts, а ответы по умолчанию компактные».

mcp/kompas_mcp_server_core.py:31 → max_faces 5000, max_edges 10000, max_vertices 10000 mcp/kompas_mcp_server_core.py:126 → json.dumps(response, ensure_ascii=False, indent=2)
P0Устаревший протокол MCP и отсутствие не-tool примитивов

Версия протокола прошита константой MCP_PROTOCOL_VERSION = "2025-06-18" и не согласуется с клиентом. Стабильная версия — 2025-11-25, а 2026-07-28 уже выпущена (статeless-ядро, Multi Round-Trip Requests вместо elicitation/sampling, кэширование списков через ttlMs/cacheScope).

Кроме того, сервер реализует только tools/*. Нет resources (дерево модели, BOM, скриншоты, журналы runtime/evidence как адресуемые ресурсы), нет prompts (готовые шаблоны «деталь по ТЗ», «проверка сборки», «чертёж + спецификация»), нет механизма подтверждения опасных операций у пользователя.

mcp/kompas_mcp_server_core.py:23 → MCP_PROTOCOL_VERSION = "2025-06-18" mcp/kompas_mcp_server_core.py:148-174 → обрабатываются только initialize / tools/list / tools/call / ping requirements.txt → pywin32, Pillow, PyMuPDF (официальный SDK "mcp" не подключён)
P0SKILL.md обещает то, чего нет в инструментах

Файл правил агента требует: «перед завершением — missing refs = 0; проверить STEP, открыв/импортировав экспортированный STEP, если STEP является результатом» и включает в QA «спецификации и экспорты, когда требуются». Но в поверхности из 35 инструментов нет ни одного инструмента экспорта (STEP/IGES/DXF/PDF) и ни одного инструмента для чертежа или спецификации.

Следствие: агент, следуя собственным правилам, вынужден уходить в kompas_run_job — то есть в написание произвольного Python — ровно там, где SKILL.md требует стабильного инструмента. Это одновременно дыра в безопасности и источник невоспроизводимости.

skills/kompas-engineering/SKILL.md:46-48 → "verify STEP by opening/importing the exported STEP" skills/kompas-engineering/SKILL.md:77 → "specifications and exports when required" mcp/kompas_mcp_server_core.py:25-59 → среди 35 имён нет export/step/dxf/drawing/specification
P0Сборка без сопряжений — модель получается «тупой»

Единственный способ разместить компонент — kompas_component_transform, задающий абсолютную жёсткую матрицу (origin + три ортонормированные оси) плюс kompas_component_translate_xy с шагом не более 5 мм. Сопряжений (совпадение, соосность, параллельность, расстояние, угол, фиксация) нет вообще.

Следствие: полученная сборка непараметрическая. Изменили деталь — в сборке ничего не перестроилось. Для реального конструкторского применения это дисквалифицирующий недостаток: у SolidWorks MCP есть AddMateCoincident, AddMateConcentric, AddMateParallel, AddMateDistance, AddMateAngle. В КОМПАС это доступно через IMateConstraint (свойства constraintType, direction, distance, fixed и коллекция IMateConstraintCollection).

mcp/kompas_mcp_server_core.py:39 → kompas_component_transform (origin + axis_x/y/z, det = +1) mcp/kompas_mcp_server.py:19 → translate_xy ограничен ±5 мм на вызов grep "mate" по src/ и mcp/ → совпадений нет
P0Трассировки стека и локальные пути утекают в ответ MCP

При любом исключении воркер возвращает traceback.format_exc() целиком. Это и утечка структуры файловой системы наружу, и мусор в контексте модели: вместо «что не так и что делать» агент получает 40 строк внутренностей.

src/worker.py:250 → "error": {"code": type(exc).__name__, "message": str(exc), "traceback": traceback.format_exc()}

Уровень P1 — надёжность и безопасность

P1Нет обработки модальных диалогов КОМПАСа

КОМПАС регулярно показывает модальные окна (запрос на перестроение, «файл изменён извне», предупреждения о ссылках). В проекте есть точечная заплата — политика rebuild_prompt_policy: auto_yes_on_copy_only в kompas_open_copy, — но общего сторожа нет. Модальное окно, которого не ждали, вешает воркер до таймаута, и все последующие запросы выстраиваются в очередь за ним.

В EPLAN MCP эта проблема решена явным инструментом eplan_watchdog — «Dismiss pending modal dialogs once», который вызывается в том числе автоматически внутри длинных операций.

mcp/kompas_mcp_server.py:52 → rebuild_prompt_policy (единственное упоминание диалогов) grep "dialog\|modal\|watchdog" по src/ → совпадений нет
P1Единственная точка отказа: один воркер, файловый транспорт, без очереди и отмены

Клиент пишет <uuid>.json в runtime/commands и опрашивает runtime/responses с шагом 80 мс и жёстким таймаутом 90 с. Воркер сортирует файлы по mtime и исполняет последовательно в одном потоке. Нет: глубины очереди, приоритетов, отмены, прогресса, ограничения числа одновременных клиентов.

Следствие: два клиента (Codex и Claude) на одном мосте — уже гонка; одна длинная COM-операция блокирует всё остальное; таймаут 90 с неотменяем и не сообщает, на каком шаге встал.

SolidWorks MCP решает это архитектурно: один Hub владеет общей COM/STA-сессией, клиенты подключаются через --proxy, обмен — по именованным каналам. Это же снимает проблему STA-потока, которую в проекте приходится решать вручную (StaDispatcher).

mcp/kompas_mcp_server_core.py:105-116 → цикл опроса, time.sleep(.08), TimeoutError src/worker.py:235-237 → while True: files = sorted(...); один поток; при отсутствии файлов sleep(.12) bootstrap/BridgeBootstrap.ps1 → сторож держит ровно один воркер
P1kompas_run_job — обход всей модели безопасности через произвольный Python

Защита джобов построена на проверке пути и поиске подстроки защищённых путей в тексте скрипта. Обойти это тривиально: собрать путь из частей, использовать chr(), работать через переменную окружения или просто открыть файл по UNC-пути. Проверка «скрипт не содержит строку c:\kompas_ai_workspace\00_source» не является границей безопасности.

При этом сам инструмент описан как «только когда стабильная поверхность не покрывает операцию» — то есть это штатный, а не аварийный путь. Учитывая, что SKILL.md сам отправляет туда агента (см. P0 выше), обход становится регулярным.

src/jobs.py:15-18 → source = script.read_text(...).lower(); if any(str(x).lower() in source for x in PROTECTED) src/jobs.py:22 → subprocess.run([sys.executable, str(script)], env=..., timeout=timeout) mcp/kompas_mcp_server_core.py:58 → kompas_run_job в публичной поверхности
P1Нет версионной матрицы поддержки КОМПАСа

Проект заявляет жёстко: «KOMPAS-3D v25 x64», Python 3.11. При этом воркер не проверяет фактическую версию запущенного КОМПАСа перед рискованной операцией. Пользователь на v21/v22/v23 получит не отказ с объяснением, а непредсказуемое поведение в середине записи.

SolidWorks MCP сделал из этого формальный механизм: SolidWorksSupportMatrix с уровнями certified / targeted / experimental / unsupported по каждой возможности и CompatibilityPolicy, который блокирует высокорисковые операции на неподтверждённых версиях, возвращая объяснение вместо попытки выполнить.

VERSION.json:43 → "kompas": "KOMPAS-3D v25 x64", "python": "3.11" grep "Version" по src/kompas_session.py → версия читается только для отчёта в kompas_status bridge/SolidWorksBridge/SolidWorks/CompatibilityPolicy.cs → CreateHighRiskWorkflowGate(...) — блокировка
P1Ссылки на объекты не переживают перестроение

Селекторы — это индекс верхнего уровня, путь в дереве (0/2/1), имя, обозначение или фрагмент имени файла. Все они «плывут» после перестроения, закрытия/открытия, смены документа или добавления компонента. В коде нет понятия устойчивого идентификатора объекта.

Это ровно та проблема, которую признаёт и параллельный проект: «3D-ссылки на объекты могут устаревать после перестроения, закрытия, восстановления или смены документа». Решение — не «аккуратнее обращаться», а явный handle, который модель видит и передаёт обратно между вызовами.

mcp/kompas_mcp_server_core.py:30 → selector: integer | string | array (индекс / путь / имя) grep "handle\|guid\|stable_ref\|persistent" по src/ → совпадений нет
P1Нет checkpoint/rollback и универсального dry-run

Каждый инструмент делает снапшот сам для себя — это отлично. Но на уровне сессии транзакции нет: если многошаговый сценарий упал на третьем шаге, откатывать первые два агент должен вручную, а инструментов для этого нет (в SolidWorks MCP есть Undo).

При этом в проекте уже есть правильный паттерн — apply=false у kompas_component_translate_xy (сухой прогон), — но он не обобщён на остальные мутирующие инструменты.

mcp/kompas_mcp_server.py:19 → "apply":{"type":"boolean","default":False} — только у translate_xy grep "checkpoint\|rollback\|undo\|dry_run" по mcp/ → совпадений нет
P1«Спящие» возможности: 5 действий недоступны агенту

В реестре воркера зарегистрированы действия, для которых нет MCP-инструмента. Агент может дотянуться до них только через произвольный Python:

  • document.activate — активировать конкретный документ
  • document.open — открыть документ
  • document.info — сведения о документе
  • model.components — список компонентов
  • view.projections — список проекций
Сравнение реестра (src/capabilities.py, src/engineering_capabilities.py) с ACTION_MAP: document.activate, document.info, document.open, model.components, view.projections — без MCP-обёртки

Уровень P2 — эксплуатация и зрелость

P2Кадрирование скриншота задано магическими числами

Обрезка вьюпорта — left: 345, top: 160, right: 8, bottom: 10 пикселей. Это калибровка под одну конкретную раскладку панелей и один DPI. На другом мониторе, при другой теме или развёрнутой панели агент получит обрезанный кадр и будет «видеть» не то, что есть.

При этом HWND документа уже получается корректно через API7 DocumentFrames — значит, прямоугольник кадра известен, и магические числа не нужны.

config/agent_config.example.json:11-17 → crop {left:345, top:160, right:8, bottom:10}
P2Нет лицензии, нет CI, нет документации по слоям

В репозитории отсутствует файл лицензии. Нет каталога .github/workflows — то есть статические тесты и контрактные тесты не запускаются автоматически, и заявленные «35 инструментов» могут разъехаться с реальностью без единого сигнала. Нет SECURITY.md, CHANGELOG, раздельной документации по установке/использованию/архитектуре.

Для сравнения: eplan-mcp-oss — Apache-2.0 и три документа docs/INSTALL.md, docs/USAGE.md, docs/ARCHITECTURE.md; SolidWorks MCP — MIT и CI с отдельным self-hosted раннером под интеграционные тесты на живом SolidWorks.

Листинг файлов репозитория: LICENSE отсутствует; .github/ отсутствует tests/: RUN_STATIC_TESTS.ps1, test_mcp_stdio.py — запуск только вручную
P2Установка тяжёлая, версия инструментов не фиксируется

Путь пользователя: распаковать ZIP в C:\KOMPAS_AI_BRIDGE, поставить зависимости вручную, запустить сторож в отдельном окне PowerShell и держать его, отдельным скриптом зарегистрировать MCP в клиенте. Для сравнения: SolidWorks MCP — один .exe с иконкой в трее и экспортом конфига; KOMPAS-3D MCP — один kompas-mcp.exe плюс config.json; EPLAN MCP — pip install "mcp[cli]".

Дополнительно: в репозитории нет снапшота схем инструментов, поэтому клиент не может обнаружить, что сервер молча изменил контракт.

CAP2_SETUP_AND_RUN.md:14-27 → ручной bootstrap + отдельное окно сторожа + отдельная регистрация requirements.txt → три строки без версий-пинов

04Чему учат MCP для SolidWorks, EPLAN и FreeCAD

Это не «хорошо бы иметь» — это уже проверенные инженерные решения в соседних САПР. Ниже — срез по осям, которые важны для КОМПАСа.

Ось SolidWorks MCP EPLAN P8 MCP KOMPAS-3D AI Bridge
Изоляция COM-сессии Один tray-Hub владеет COM/STA, клиенты — прокси по именованным каналам Add-in внутри EPLAN, MCP-сервер общается через мост по сменяемому транспорту Один воркер + файловый транспорт, опрос раз в 80 мс
Версионная политика Матрица certified/targeted/experimental/unsupported, блокировка рискованных операций Не формализована Жёстко «v25», проверки версии перед записью нет
Сопряжения сборки Coincident / Concentric / Parallel / Distance / Angle — Нет (только абсолютная матрица)
Одноклик-сценарии CutFaceByProjectedEdges, ReplaceNestedComponentAndVerifyPersistence, ReviewTargetedStaticInterference eplan_export_pdf, eplan_rename_tag и др. Есть атомарные операции, составных сценариев почти нет
Диалоги / сбои UI Явные тесты поверхности ошибок (ToolErrorSurfaceTests) eplan_watchdog — гасит подвисшие модальные окна Только частная заплата для запроса перестроения
Проверка состояния DiagnoseActiveDocumentHealth — перестроение + диагностика как обязательный шлюз eplan_status Есть kompas_status, но без диагностики перестроения
Контекст-бюджет Структурированные компактные ответы Списки страниц/устройств — короткие Полные дампы до 5000 граней в контекст
Расширяемость Слои app / bridge / tests, отдельные сервисы по доменам «Framework»: документированный протокол сообщений + reference add-in Монки-патч реестра (register_geometry_translate) + дописывание инструментов строковым поиском
Упаковка Один .exe, иконка в трее, экспорт конфига pip install "mcp[cli]" ZIP + ручной bootstrap + сторож в отдельном окне
CI CI + релизные workflow + self-hosted раннер под интеграционные тесты — Нет workflow
Лицензия MIT Apache-2.0 Отсутствует

Отдельно стоит отметить параллельный проект KOMPAS-3D MCP — он закрывает те же задачи с другой стороны и полезен как источник идей, а не как конкурент:

  • CAD-as-Code: execute_tdcad_script, execute_geometry_script (компактный DSL), scenario_runner для повторяемых сценариев;
  • Экономия контекста: большие результаты уходят в runtime memory / resources / artifacts, ответы по умолчанию компактные;
  • Надёжность: preflight-проверки, snapshot/diff, безопасное создание features, selection helpers;
  • Покрытие: полноценный 2D (чертежи, виды, слои, размеры, штамп, DXF) — то, чего в разбираемом проекте нет совсем.

А из FreeCAD MCP стоит взять одну вещь: аддон, живущий внутри САПР и поднимающий RPC-сервер. Это принципиально устойчивее, чем внешний COM-attach: не нужно угадывать окно, PID и elevation, и нет класса ошибок «подключились не к тому экземпляру».

05Двадцать четыре конкретных улучшения

Сгруппировано по пяти блокам. Для каждого пункта указано, что делать и какой практикой это подтверждено.

Блок A. Протокол и архитектура

#УлучшениеЧто конкретно сделатьПриоритет
A1 Перейти на официальный MCP SDK Заменить самописный JSON-RPC на mcp[cli] / FastMCP. Бесплатно получаете: согласование версии протокола, resources, prompts, прогресс, отмену, структурированный вывод, аннотации. Заодно исчезает обёртка kompas_mcp_server.py, которая дописывает инструменты поиском подстроки. P0
A2 Один декларативный каталог инструментов Описать все инструменты (имя, схема, аннотации, действие реестра, требуемые права) в одном месте; генерировать из него и tools/list, и ACTION_MAP, и VERSION.json. Добавить контрактный тест-снапшот, чтобы поверхность не могла разъехаться молча. P0
A3 Актуализировать версию протокола Поддержать 2025-11-25 как базовую и добавить ветку под 2026-07-28 (stateless-ядро, MRTR вместо elicitation, ttlMs/cacheScope в ответах списков). Версию согласовывать, а не прошивать. P0
A4 Отдать состояние как resources Опубликовать ресурсы: kompas://doc/active/tree, kompas://doc/active/bom, kompas://doc/active/bbox, kompas://runtime/evidence/<id>, kompas://jobs/allowlist, скриншоты как image/png. Тогда большие дампы читаются по требованию, а не вбрасываются в контекст. P0
A5 Добавить prompts Шаблоны: «деталь по ТЗ», «проверка сборки на пересечения», «чертёж + спецификация», «диагностика почему вырез не виден». Это снимает вариативность и снижает число шагов у модели. P1
A6 Hub вместо файлового транспорта Один процесс-владелец COM/STA (иконка в трее), клиенты — через именованные каналы. Добавить очередь с приоритетами, отмену, прогресс, ограничение числа клиентов, TTL запроса. По образцу SolidWorks MCP (client → proxy → hub → tools → CAD). P1
A7 Реестр возможностей через плагины, а не монки-патч Заменить REGISTRY["x"] = f и register_geometry_translate(REGISTRY, ok) на явный реестр с дескрипторами (имя, схема, права, домен). Тогда geometry_translate.py, jobs.py и остальное подключаются одинаково. P2

Блок B. Инженерная полнота

#УлучшениеЧто конкретно сделатьПриоритет
B1 Сопряжения сборки Добавить семейство: kompas_mate_add (совпадение, параллельность, перпендикулярность, соосность, касание, расстояние, угол, фиксация), kompas_mate_list, kompas_mate_delete, kompas_rebuild. Опорные интерфейсы КОМПАС: IMateConstraint (constraintType, direction, distance, fixed) и IMateConstraintCollection. Это превращает сборку из «набора тел» в параметрический узел. P0
B2 2D-документация: чертёж, штамп, DXF Семейство инструментов для CDW: создать чертёж из модели, вставить стандартные виды (спереди/сверху/слева/изометрия), проставить размеры, заполнить штамп, экспортировать в DXF/PDF. В коде уже есть зацепка — LayoutSheets.Item(0).Stamp в capabilities.py. В реальном КБ это и есть основная рутина. P0
B3 Спецификация (SPW) Генерация и чтение спецификации: состав из дерева сборки, разделы, обозначения, количества, экспорт. У проекта уже есть корректный kompas_bom_read на базе IPart7 + CreateSpcObjects/InheritExclude — остаётся «донести» его до документа спецификации. P1
B4 Экспорт STEP/IGES + верификация импортом Добавить kompas_export (STEP/IGES/DXF/PDF) и kompas_import_verify. Это закрывает обещание SKILL.md, которое сейчас нечем выполнить, и убирает повод идти в run_job. P0
B5 Отверстия: грани, цековка, резьба Сейчас kompas_part_add_hole умеет только плоскость XOY и вырез-выдавливанием. Добавить посадку на выбранную грань, типы (цековка, зенковка, резьбовое), серии отверстий, и — где API это позволяет — настоящий IHole3D. Урок SolidWorks: эскиз на грани радикально устойчивее эскиза в свободном пространстве. P1
B6 Размеры и PMI: расширить семейства kompas_pmi_dimension_create сейчас умеет только линейный размер на XOY. Добавить диаметральные, радиальные, угловые, координатные/от-базовые, допуски и шероховатость. Без этого чертёж не выпустить. P1
B7 Составные «одноклик»-сценарии По образцу CutFaceByProjectedEdges: один инструмент = проверенная последовательность, а не цепочка примитивов, которую модель должна угадать. Кандидаты: «плита с отверстиями по массиву», «втулка», «кронштейн с бобышкой и фаской», «сборка из N компонентов с сопряжениями». P1
B8 Выставить «спящие» возможности Оформить инструментами document.activate, document.open, document.info, model.components, view.projections — они уже реализованы в реестре, но недоступны агенту. P1

Блок C. Надёжность и безопасность

#УлучшениеЧто конкретно сделатьПриоритет
C1 Подключить конфиг к политике безопасности Заставить safety.py читать protected_roots/write_roots из agent_config.json (сейчас load_config() вообще не вызывается). Убрать абсолютные пути из исходников, оставить безопасные значения по умолчанию. P0
C2 Сторож модальных диалогов Инструмент kompas_dismiss_dialogs + автоматический вызов внутри длинных операций, с записью в evidence того, что и когда было погашено. Прямая аналогия — eplan_watchdog. P0
C3 Гейт подтверждения для разрушающих операций Через elicitation (2025-11-25) или MRTR (2026-07-28) спрашивать подтверждение перед save, удалением, записью вне work. Аннотации readOnlyHint/destructiveHint у вас уже проставлены — но это лишь подсказки клиенту, а не защита. P1
C4 Заменить run_job на типизированные операции Убрать произвольный Python из штатной поверхности. Вместо него: (1) явный манифест разрешённых операций вместо поиска подстроки в тексте скрипта; (2) запуск в процессе с белым списком импортов; (3) постепенная замена на «одноклик»-инструменты из B7, чтобы обход стал не нужен. Если CAD-as-Code нужен как продукт — вынести его в отдельный, явно помеченный небезопасный профиль, который пользователь включает осознанно. P0
C5 Версионная матрица поддержки КОМПАС Таблица уровней (certified/targeted/experimental/unsupported) по версиям КОМПАС и по группам возможностей, с проверкой фактической версии через COM перед рискованной операцией и отказом с понятным текстом на неподтверждённой версии. Прямой перенос CompatibilityPolicy из SolidWorks MCP. P1
C6 Классификация ошибок и редакция данных Убрать traceback из ответов MCP. Ввести устойчивые коды (kompas_not_attached, path_not_allowed, active_document_mismatch, geometry_verification_failed, timeout_no_progress) плюс поле hint с тем, что делать. Трассировки — только в локальный журнал. P0
C7 Диагностика как обязательный шлюз Инструмент kompas_health (аналог DiagnoseActiveDocumentHealth): перестроение, число ошибок/предупреждений дерева, возраст heartbeat воркера, глубина очереди, время последней операции, последняя ошибка. SKILL.md уже требует проверять дерево — пусть это будет одна команда. P1

Блок D. Опыт работы агента

#УлучшениеЧто конкретно сделатьПриоритет

D3 Слой «сначала выбор» Добавить kompas_list_entities, kompas_resolve_selection (по описанию: «верхняя плоская грань», «внутренняя цилиндрическая»), kompas_edit_state (не в режиме ли редактирования эскиза). D5 Checkpoint / rollback сессии Инструменты kompas_checkpoint / kompas_rollback на уровне воркера, чтобы откатывать многошаговый сценарий одной командой, а не вручную. Аналог Undo в SolidWorks MCP. P1
D6 Самокалибровка кадра скриншота Вычислять прямоугольник вьюпорта из DocumentFrames вместо чисел 345/160/8/10; учитывать DPI и расположение панелей. Добавить проверку «кадр не пустой и изменился» — она в проекте уже частично есть в kompas_rotate_view, стоит сделать общей. P1
D7 Обновить SKILL.md под реальную поверхность Пока нет инструментов экспорта и чертежей — либо убрать требования про STEP и спецификации, либо (правильнее) добавить инструменты из B2–B4. Файл правил не должен описывать несуществующие возможности: агент будет искать обход. P0

06Дорожная карта: три волны

Порядок выбран так, чтобы каждая волна давала законченный результат, а не полуфабрикат.

Волна 1Фундамент
Цель: перестать терять контекст, убрать утечки, подключить конфиг, честно объявить версию протокола.
  • A1, A2, A3 — SDK, единый каталог инструментов, актуальный протокол
  • A4 — ресурсы вместо полных дампов
  • D1 — компактные ответы и постраничность
  • C1 — конфиг управляет политикой безопасности
  • C6 — коды ошибок вместо трассировок
  • C2 — сторож модальных диалогов
  • D7 — привести SKILL.md в соответствие с реальностью
Волна 2Инженерная полнота
Цель: проект должен уметь делать то, ради чего конструктор вообще открывает САПР.
  • B1 — сопряжения сборки (главный приоритет)
  • B2 — чертёж, виды, размеры, штамп, DXF
  • B3 — спецификация
  • B4 — экспорт STEP/IGES + верификация импортом
  • C4 — закрыть run_job типизированными операциями
  • B5, B6 — отверстия по граням и расширенные размеры
  • C5 — версионная матрица
  • C7 — инструмент диагностики
Волна 3Масштаб и продукт
Цель: устойчивость под нагрузкой, переносимость, публичная зрелость.
  • A6 — Hub с очередью, отменой и прогрессом
  • D2, D3 — устойчивые ссылки и слой выбора
  • D4, D5 — сухой прогон и checkpoint/rollback
  • B7, B8 — составные сценарии и «спящие» возможности
  • D6 — самокалибровка кадра
  • E1–E5 — упаковка, CI, лицензия, документы

07Как измерять, что стало лучше

Токенов на типовой сценарийДолжно упасть кратно после D1 + A4: сейчас один вызов топологии способен отдать десятки тысяч токенов.
Доля сценариев без ручного вмешательстваОт постановки задачи до сохранённого и проверенного результата. Основной барьер сегодня — отсутствие сопряжений и чертёжных инструментов.
Число обращений к run_jobДолжно стремиться к нулю. Любой вызов — сигнал, что в стабильной поверхности не хватает операции.
Расхождения после reopenОпераций, где данные до и после Save → Close → Reopen разошлись. Должно быть строго 0.
Время до первого отказа с понятной причинойПосле C6: пользователь должен видеть код и подсказку, а не трассировку Python.
Покрытие поверхности тестамиДоля из 35 (и далее больше) инструментов, у которых есть контрактный тест на схему и smoke-тест на живой КОМПАС.

Итог в трёх предложениях

Проект уже сделал главное и самое трудное — построил детерминированный слой с доказательной записью, который не даёт ИИ «нафантазировать» инженерные данные, и это ценнее большинства публичных MCP для САПР. Но у него проседают три вещи: протокол и контекст (устаревшая версия MCP, полные дампы в контекст, не подключённый конфиг), инженерная полнота (нет сопряжений, нет 2D-документации, нет экспорта — при том что собственные правила агента их требуют) и устойчивость (нет сторожа диалогов, нет версионной матрицы, нет очереди и отмены). Первая волна изменений — протокол, контекст, конфиг и коды ошибок — даёт эффект сразу и почти без риска; вторая — сопряжения и чертежи — превращает проект из демонстратора в рабочий инструмент.
