# Волна 11 — электрорасчёт щита

**Поверхность:** 53 → 54 (`kompas_cabinet_calc`).
**Тесты:** 395 → 455 (60 новых, `tests/test_wave11.py`).

## Что добавлено

`src/cabinet_calc.py` — чистые функции, без COM. Один инструмент
`kompas_cabinet_calc` с полем `kind` на восемь видов расчёта.

### Считается без таблиц (физика и арифметика)

| `kind` | Что делает | Формула |
|---|---|---|
| `current` | ток по мощности | `I = P / (√3 · U · cos φ · η)`, для одной фазы без `√3` |
| `voltage_drop` | потеря напряжения | `ΔU = √3 · I · (R·cos φ + X·sin φ)`, `R = ρ·L/S` |
| `fault_current` | ток КЗ | `Iкз = U / (√3 · |Zист + Zлин|)` |
| `derating` | поправочные коэффициенты | произведение факторов |

Источник для `fault_current` задаётся тремя способами: `source_impedance_ohm`,
`source_short_circuit_mva` или `transformer{power_mva, uk_percent}`.

### Требует нормативных таблиц (иначе отказ)

| `kind` | Таблица | Строки |
|---|---|---|
| `max_demand` | `demand_factors` | `{load_type, kc}` |
| `cable_size` | `ampacity` | `{section_mm2, current_a}` |
| `breaker_select` | `breakers` | `{rating_a, trip_curve, breaking_ka, ...}` |
| `selectivity` | `trip_curves` | `{rating_a, trip_curve, points[{multiple, t_min_s, t_max_s}]}` |

Таблица передаётся в поле `tables`: списком строк или как `{"rows": [...],
"source": "..."}`. Источник возвращается в `provenance`.

## Ключевое решение: отказ вместо экстраполяции

Нормативных таблиц внутри модуля **нет** — это принципиально. Допустимые токи
кабелей, каталог аппаратов и время-токовые характеристики суть нормы и каталоги
производителей; хранить их в коде значило бы превратить отказ в невозможность.

Отсюда три поведения:

1. **Нет таблицы → `refusals`**, пустой `result`, а не подобранное «на глаз»
   сечение. Пустой ответ полезнее правдоподобного: первый виден сразу.
2. **Нет данных для критерия → `not_checked`**, а не «прошло». Если предел
   потери напряжения не задан, сечение выбирается только по току, но ответ
   об этом сообщает.
3. **Ток вне характеристики → не экстраполируется.** Селективность возвращает
   `selective: null` и причину «ток вне диапазона характеристики». Попадание
   между узлами даёт интерполяцию, помеченную словом `interpolated` с
   предупреждением, что характеристики логарифмические и линейная интерполяция
   груба.

Поле `verdict` повторяет логику волны 10: `computed`, `computed_with_gaps`
(есть непроверенное) или `refused`.

## Что оператор заметит

- Вызов без `tables` для нормативного расчёта вернёт `ok: false` и код
  `no_table` с названием нужной таблицы в `required_table`.
- Таблица без `source` считается, но ответ помечает: источник нормы неизвестен,
  результат нельзя проверить по первоисточнику.
- Однофазная петля «фаза-нуль» без `zero_sequence_impedance_ohm` не считается
  вовсе — это не консервативная оценка, а неизвестная величина.

## Честные ограничения

- **Удельное сопротивление** — физическое свойство металла при 20 °C
  (медь 0.01754, алюминий 0.02899 Ом·мм²/м). Поправка на рабочую температуру,
  способ прокладки и группировку вносится вызывающей стороной через `factors`.
- **Расчёт не сверялся с расчётом проектировщика** на реальном щите. Формулы
  стандартные, но приёмка по проекту остаётся за инженером.
- **Кабели и аппараты не подбираются «из интернета»**: подбор идёт только по
  переданному каталогу, что исключает выдуманные артикулы.
- Модуль **не читает КОМПАС** и не влияет на модель: это калькулятор.

## Дефекты, найденные прогоном

1. `load_current` распаковывал результат `calc_current` как кортеж — любой
   расчёт сечения по мощности, а не по току, падал с `ValueError`. Поймано
   тестом, а не чтением кода.
2. При задании длины без сечения (или наоборот) сопротивление линии молча
   обнулялось, и ток КЗ получался завышенным. Теперь это отдельное
   примечание в `notes`.
3. В строке документации модуля проскочило `по_normе` — поправлено.

Ещё три падения были на неверных ожиданиях в тестах: предел потери в 2 % на
120 м не проходит даже 6 мм² (это отсутствие решения, а не повод «взять
побольше»); сравнение по время-токовой характеристике при попадании в узел
даёт интерполированное время вышестоящего аппарата, а не провал; признак
«физическое свойство» объявлен в `LIMITS`, а не в строке документации.

## Пример вызова

```json
{
  "kind": "cable_size",
  "power_kw": 15, "voltage_v": 380, "cos_phi": 0.9,
  "length_m": 40, "material": "copper",
  "drop_limit_percent": 5.0,
  "factors": [{"name": "temperature", "value": 0.9}],
  "tables": {"ampacity": {"source": "ПУЭ 7-е изд., табл. 1.3.4",
                          "rows": [{"section_mm2": 1.5, "current_a": 23},
                                   {"section_mm2": 2.5, "current_a": 30},
                                   {"section_mm2": 4, "current_a": 41}]}}
}
```

Ответ: `selected.section_mm2 = 2.5`, `provenance.source = "ПУЭ 7-е изд., табл.
1.3.4"`, `verdict = computed`.
