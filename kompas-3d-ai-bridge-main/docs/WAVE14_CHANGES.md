# Волна 14: спецификация и маркировка щита из раскладки

## Что закрыто

Второй по цене остаток против конкурентов: **конфигуратор щита как изделия —
спецификация и маркировка**. До этой волны мост умел проверить состав, рассчитать
раскладку, материализовать её и сверить перечень с уже существующим документом,
но **сам перечень из раскладки не рождался**: он только читался. Поле `labels` в
модели раскладки оставалось пустым. Щит можно было разложить и построить, но
нельзя было получить из этого документ.

Машина с КОМПАС для этой задачи не нужна: перечень, обозначения и шильды — это
данные. Запись их в документ КОМПАС остаётся за волной, которой нужен живой
КОМПАС.

## Новый модуль `src/cabinet_spec.py`

Чистые функции, без COM. Один вид на входе — три вида на выходе:

| `kind` | Что отдаёт |
|---|---|
| `bom` | перечень: что стоит, сколько, какого габарита и в каких координатах |
| `marking` | позиционные обозначения по ГОСТ 2.710-81 (QF1, KM1, XT1…) |
| `labels` | шильды: обозначение, текст и координаты для нанесения |

Нумерация идёт **по порядку расположения на плате** — сверху вниз, затем слева
направо, — а не по алфавиту наименований. Обозначение должно читаться так, как
оно читается глазами на щите: QF1 левее QF2, даже если «Контактор» в списке
выше «Автомата».

## Буквенные коды: откуда они берутся

Код берётся одним из трёх способов, в порядке приоритета:

1. **явно** — поле `codes`: `{"brk": "QF"}`. Высший приоритет: если инженер
   знает код, модуль его не переспрашивает;
2. **по виду изделия** — поле `kinds` плюс таблица соответствия
   `designation_map` из реестра нормативных таблиц. Источник таблицы
   возвращается в `provenance`;
3. **никак** — тогда позиция уходит в `unresolved` с указанием причины.

### Почему соответствие помечено как составленное

`data/normative/designations.json` — 104 кода, добытые из открытой публикации
ГОСТ 2.710-81. Это **цитата**: код и вид элемента схемы.

`data/normative/designation_map.json` — соответствие «вид изделия щита → код».
Это **не цитата**: в ГОСТ 2.710-81 коды заданы для видов элементов схемы, а не
для видов изделий щита, и такого соответствия в стандарте нет. Оно составлено и
прямо помечено в `source.note`. Выдавать составленное соответствие за цитату из
стандарта — подмена, поэтому различие зафиксировано в данных.

## Отказ вместо выдумывания

- **Для УЗО в ГОСТ 2.710-81 кода нет.** Отдельного вида элемента «устройство
  защитного отключения» в таблице кодов нет. Позиция **не получает код
  автоматического выключателя**, а уходит в `unresolved`, и в `code_refusals`
  появляется запись `no_code_for_kind`. Инженер задаёт код сам через `codes`.
- Позиция, чей `lib_key` отсутствует в `library`, не получает «типового»
  наименования: `name` остаётся `None`, позиция уходит в `unverified`.
- Вид изделия, которого нет в таблице соответствия, — отказ `kind_not_in_table`,
  а не подбор похожего.
- Пустая раскладка — отказ `empty_layout`. Ни одного присвоенного обозначения —
  для `labels` отказ `no_designations`: наносить нечего.

## Интеграция: ответ раскладчика передаётся целиком

`kompas_cabinet_layout_build` отдаёт `{"ok": ..., "layout": {...}}`. Функция
`unwrap` разворачивает эту обёртку, если `elements` и `groups` не переданы
явно, — иначе звено «раскладка → спецификация» существовало бы только на
словах, а пользователь разбирал бы ответ руками. Явно переданные `elements`
при этом выигрывают: обёртка не затирает то, что задано напрямую.

Проверено тестом: раскладка из трёх строк (2 автомата, контактор, 3 клеммы)
даёт 6 обозначений с кодами QF, KM, XT.

## Тесты

`tests/test_wave14.py` — 29 тестов. Всего 567 (было 538).

Что проверяется сверх очевидного:

- группа разворачивается в позиции с шагом по габариту (5 клемм по 6 мм дают
  x = 10, 16, 22, 28, 34);
- нумерация внутри кода идёт по координате, а не по имени;
- явный код перебивает код из таблицы;
- УЗО остаётся без обозначения;
- `designation_map` помечен как составленный, а не процитированный;
- таблица `designations` — реальная, более 50 строк, источник ГОСТ 2.710-81;
- ответ `kompas_cabinet_layout_build` передаётся следующим вызовом целиком.

## Ошибки, найденные тестами

1. **`_assign` возвращал 4 значения вместо 5** на пустой раскладке —
   `ValueError: not enough values to unpack`. Вызывающие разбирали два разных
   формата; теперь пустая раскладка возвращает тот же пятиэлементный кортеж.
2. **Ответ раскладчика не разворачивался** — передача `build_layout` дальше
   давала `empty_layout`. Появилась `unwrap`.

## Что осталось внутри этой задачи

- **Запись перечня и маркировки в документ КОМПАС.** Здесь только данные.
  Требуется машина с КОМПАС.
- **Формат перечня по ГОСТ 2.106** (графы, размеры, основная надпись) — сейчас
  структура данных, а не оформленный бланк.
- **Маркировка клемм по ГОСТ 2.710** с нумерацией зажимов внутри ряда: сейчас
  каждая клемма получает свой XT по порядку, а не `XT1:1…XT1:5`.

## Ограничения

Записаны в `LIMITS` модуля и возвращаются в каждом ответе:

- перечень строится из раскладки — чего нет в `library`, того нет в перечне с
  достоверным наименованием;
- соответствие вида изделия коду составлено, а не процитировано;
- для УЗО кода в ГОСТ 2.710-81 нет;
- запись в документ КОМПАС здесь не производится.
