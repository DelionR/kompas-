# Волна 2: сопряжения сборки и проверка артефактов

Изменения второго приоритета из плана аудита: сборка перестала быть набором
независимо висящих компонентов, а результат экспорта перестал считаться
успешным только потому, что COM-метод не бросил исключение.

Всё в этой волне проверяется **без КОМПАСа**: 39 тестов в `tests/test_wave2.py`
плюс 42 теста волны 1 и существующие контрактные тесты.

## Проверка

```powershell
cd <bridge_root>
python -m unittest discover -s tests -p "test_wave2.py" -v
python -m unittest discover -s tests -p "test_wave1.py"
python tests\test_mcp_stdio.py
python tests\test_mcp_bridge_routing.py
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\RUN_STATIC_TESTS.ps1 -Root (Resolve-Path .)
```

## Что сделано

### 1. Сопряжения сборки (B1)

**Было.** Мост умел вставить компонент (`kompas_assembly_insert_component`) и
задать ему абсолютную позу (`kompas_component_transform`). Связей между
деталями не было ни одной: сборка оставалась набором независимо висящих тел,
и повод «доделать руками в КОМПАСе» оставался.

**Стало.** `src/mate_tools.py` и два инструмента:

* `kompas_mate_read` - чтение сопряжений активной сборки: тип, направление,
  числовое значение, признак фиксации, имена участников;
* `kompas_mate_create` - создание **одного** сопряжения за вызов.

Поддержаны семь типов: `coincident`, `parallel`, `perpendicular`,
`concentric`, `tangent` (без числового параметра) и `distance`, `angle`
(числовой параметр обязателен).

Валидация вынесена в чистые функции и проверяется тестами без КОМПАСа:

* значение, переданное для типа, который его не принимает, - ошибка, а не
  молчаливое игнорирование;
* отсутствие обязательного значения - ошибка;
* `distance` ограничен 10 000 мм, `angle` - 360°, значение должно быть
  конечным и положительным;
* сборка обязана быть `*_AGENT_COPY.a3d` в рабочем каталоге моста;
* два селектора, указывающие на один и тот же компонент, отклоняются до
  открытия файла.

Транзакционная обвязка повторяет принятый в проекте порядок: байтовый снимок,
проверка точного активного `PathName`, создание, проверка роста числа
сопряжений, `Save` → `Close` → `Reopen`, повторное чтение, восстановление
прежнего активного документа; при любой ошибке - откат из снимка.

**Границы честности.** Интерфейс сопряжений (`IMateConstraint` /
`ksMateConstraint`) в разных версиях КОМПАСа называется по-разному, а
подтверждённого стенда под рукой не было. Поэтому модуль **не утверждает**,
что умеет создавать сопряжения:

* имена коллекции и методов перебираются из списка известных вариантов;
* если ни один не подошёл, поднимается `mate_create_interface_not_available`
  со списком испробованного, а не тихая подмена результата;
* в ответе всегда есть блок `interface` с фактически сработавшим путём
  (`read_source`, `create_method`) - его и нужно занести в матрицу версий;
* `kompas_mate_read` при ненайденной коллекции возвращает
  `interface.confirmed = false` и объяснение, а **не** пустой список, который
  можно принять за «сопряжений нет».

Геометрическая корректность сопряжения не проверяется: для этого нужен анализ
степеней свободы, и он в эту волну не входит. Об этом прямо сказано в
`warnings` ответа.

### 2. Проверка артефактов экспорта (B4, частично)

**Было.** Единственным доказательством успешного экспорта было отсутствие
исключения. COM-метод возвращает управление и тогда, когда файл получился
пустым, обрезанным или содержит только заголовок, поэтому агент мог объявить
выгрузку выполненной по пустышке.

**Стало.** `src/artifact_check.py` и инструмент `kompas_artifact_check`,
который проверяет **содержимое** файла:

| Формат | Что проверяется |
|---|---|
| STEP | сигнатура `ISO-10303-21`, закрывающий `END-ISO-10303-21`, число сущностей, наличие `MANIFOLD_SOLID_BREP` / `ADVANCED_FACE`, `FILE_SCHEMA` |
| DXF | список секций, наличие `ENTITIES`, маркер `EOF`, число сущностей по типам, `$ACADVER`, `$INSUNITS` |
| PDF | версия из заголовка, завершающий `%%EOF`, число страниц |
| PNG | сигнатура, чанк `IHDR`, реальные ширина и высота, `IEND` |

Дополнительно:

* формат определяется по расширению, а при несоответствии - по сигнатуре;
* файл больше 32 МБ читается частично, и это **не скрывается**:
  `scan_truncated` и предупреждение в `warnings`;
* неподдерживаемый формат даёт `ok: false` с кодом
  `unsupported_artifact_kind`, а не «похоже, всё хорошо»;
* читать можно только внутри `work/` и разрешённых корней записи; выход за
  них - `path_outside_approved_roots`;
* в каждом вердикте есть блок `limits`, который прямо говорит: проверка
  структурная, совпадение геометрии с моделью ею не подтверждается.

Модуль не зависит от COM, поэтому проверяется тестами целиком - включая
синтетические STEP, DXF, PDF и PNG, собранные в самих тестах.

## Изменения, заметные оператору

1. **Поверхность выросла с 35 до 38 инструментов.** Три новых:
   `kompas_mate_read`, `kompas_mate_create`, `kompas_artifact_check`.
   `VERSION.json` обновлён, контрактный тест это проверяет.
2. **`kompas_mate_create` пишет не более одного сопряжения за вызов.** Пакетная
   запись не позволяет понять, какое именно сопряжение разъехалось, если после
   перестроения модель поехала.
3. **`kompas_mate_create` требует, чтобы активным был `*_AGENT_COPY.a3d`** в
   рабочем каталоге моста. Сопряжения в исходную сборку не пишутся никогда.
4. **`kompas_artifact_check` читает только разрешённые корни.** Проверить
   произвольный файл на диске через него нельзя.
5. **Версия сборки не поднята** - осталась `1.1.14_CAP2`. Строка зашита в десяти
   местах, включая `tests/build_cap2_golden.py`, который собирает golden-пакет;
   поднятие версии - отдельный релизный шаг, а не побочный эффект правки кода.
6. **Тест `test_wave1.py` обновлён осознанно:** ожидаемое число инструментов
   изменено с 35 на 38. Это и был его смысл - заставить заметить изменение
   поверхности.

## Чего в этой волне нет

Осознанно отложено:

* чертежи, основная надпись, экспорт DXF как операция (B2);
* спецификация как документ, а не только чтение BOM (B3);
* сам экспорт STEP через COM - в этой волне сделан только **контроль**
  результата; сама выгрузка по-прежнему идёт через `kompas_run_job` либо
  руками;
* сторож модальных диалогов (C2) - требует живого КОМПАСа для проверки;
* версионная матрица КОМПАСа (C5) - сопряжения дают для неё первый реальный
  материал: зафиксировать фактически сработавшие имена интерфейсов;
* устойчивые ссылки на объекты (D2), сухой прогон для всех мутирующих
  инструментов (D4), checkpoint/rollback (D5);
* самокалибровка кадра скриншота (D6);
* упаковка, CI, лицензия (E1-E3).

Актуальный список приоритетов - в отчёте `KOMPAS-3D_AI_Bridge_audit_plan.html`.
