## Что сделано

### 1. Сторож модальных диалогов (C2)

**Было.** Застрявший модальный диалог останавливал весь мост: COM-вызовы
начинали висеть, воркер уходил в таймаут, и агент не мог отличить «операция
не удалась» от «КОМПАС ждёт нажатия кнопки». В `winui.py` был только поиск
главного окна.

**Стало.** `src/dialogs.py` (классификация) и две функции в `src/winui.py`
(перечисление и закрытие), плюс инструмент `kompas_dialogs`.

Ключевое решение: **сторож не использует COM**. Если КОМПАС висит на
модальном окне, обращение через Automation повиснет на том самом окне,
которое нужно продиагностировать. Поэтому процесс ищется через `tasklist`,
а окна - через Win32 `EnumWindows` с фильтром по классу диалога `#32770`.

Политика из трёх уровней:

| Политика | Что попадает | Что делает мост |
|---|---|---|
| `close` | информационные окна с единственной кнопкой подтверждения | может закрыть по `apply=true` |
| `report` | вопросы, сохранение, выбор файла, ошибки, предупреждения, настройки, **неизвестные окна** | только сообщает |
| `ignore` | окна прогресса, скрытые окна, окна не-диалоговых классов | не трогает |

Почему так: у окна «Сохранить изменения?» крестик означает «не сохранять»,
и автозакрытие такого окна - это потеря данных. Поэтому всё, что связано с
выбором, сохранением и файлами, получает `report`, а незнакомое окно тоже
попадает в `report`, а не закрывается наугад.

Ограничения соблюдены явно: `apply` по умолчанию `false` (инструмент только
читает), за вызов закрывается не больше трёх окон, остальные честно
перечисляются как отложенные.

### 2. Матрица подтверждённых версий (C5)

**Было.** Версия КОМПАСа читалась только для отчёта в `kompas_status`.
Мост вызывал десятки интерфейсов API5/API7, не зная, существуют ли они в
этой сборке. На неподтверждённой версии инструмент мог сделать не то, а
агент не имел способа отличить «работает» от «повезло».

**Стало.** `src/version_matrix.py` и инструмент `kompas_version_check`.

Матрица живёт в конфиге, в секции `kompas.version_matrix`:

```json
{
  "kompas": {
    "version_matrix": {
      "entries": [
        {"pattern": "25.*", "level": "certified", "notes": "проверено на v25 x64"}
      ],
      "default_level": "unverified",
      "guarded_actions": ["mate.create"]
    }
  }
}
```

Уровни: `certified`, `targeted`, `experimental`, `unsupported`, `unverified`.
Действия из `guarded_actions` разрешены только на `certified` и `targeted`;
на остальных поднимается `kompas_version_not_verified` с объяснением, что
делать.

Три решения, которые стоит отметить:

* **Пустая матрица ничего не запрещает.** Уровень по умолчанию -
  `unverified`, то есть «не проверено», а не «запрещено». Поведение
  существующей установки не меняется, пока оператор не заполнит матрицу.
* **Номера версий не выдуманы.** Матрица - утверждение оператора «на этой
  сборке проверено», а не догадка автора кода. Именно поэтому в примере
  конфига `entries` пуст.
* **Версия запрашивается только при защите.** `guard_for_session` сначала
  смотрит, есть ли действие в `guarded_actions`, и только потом обращается
  к COM. На обычных вызовах накладных расходов нет, а результат кэшируется
  в сессии. Тест проверяет это счётчиком обращений: для незащищённого
  действия `status()` не вызывается ни разу.

Разбор версии учитывает, что в названии продукта есть посторонние цифры:
`KOMPAS-3D V25.0` → `(25, 0)`, `25.0.0.1234` → `(25, 0, 0, 1234)`,
а `KOMPAS-3D` без номера не разбирается вообще (и это попадает в `warnings`,
а не превращается в догадку).

## Изменения, заметные оператору

1. **Поверхность выросла с 38 до 40 инструментов:** `kompas_dialogs`,
   `kompas_version_check`. `VERSION.json` обновлён.
2. **Появилась секция `kompas.version_matrix` в конфиге.** Отсутствие секции
   безопасно: матрица пуста, ничего не блокируется.
3. **Заполнив `guarded_actions`, вы можете заблокировать себе работу.**
   Действие из этого списка на версии вне `certified`/`targeted` будет
   отклоняться. Это и есть цель, но знать об этом нужно заранее.
4. **`kompas_dialogs` по умолчанию ничего не закрывает.** Закрытие окон
   требует `apply=true`, и это осознанное действие, а не побочный эффект
   диагностики.
5. **Тесты `test_wave1.py` и `test_wave2.py` обновлены осознанно** -
   ожидаемое число инструментов теперь 40. Это их работа: заставить заметить
   изменение поверхности.
6. **Версия сборки снова не поднята** - осталась `1.1.14_CAP2`, по той же
   причине, что и в волне 2: строка зашита в десяти местах, включая сборку
   golden-пакета.

## Чего в этой волне нет

* чертежи, основная надпись, экспорт DXF как операция (B2);
* спецификация как документ (B3);
* сам экспорт STEP через COM (B4) - контроль результата сделан в волне 2;
* устойчивые ссылки на объекты (D2), сухой прогон для всех мутирующих
  инструментов (D4), checkpoint/rollback (D5);
* самокалибровка кадра скриншота (D6);
* упаковка, CI, лицензия (E1-E3).

Отдельно про сторож: шаблоны заголовков неполны по определению, потому что
живого стенда с диалогами КОМПАСа под рукой не было. Незнакомое окно
получает `report` - безопасное поведение, но список шаблонов стоит
пополнять по мере реальных наблюдений.
