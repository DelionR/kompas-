# Волна 4: экспорт с проверкой результата и контрольные точки

Изменения четвёртого приоритета: экспорт перестал считаться выполненным по
факту возврата из COM-метода, а снимки перед записью превратились из
одноразовых файлов в управляемые контрольные точки.

Всё проверяется **без КОМПАСа**: 31 тест в `tests/test_wave4.py` плюс 42 теста
волны 1, 39 - волны 2, 41 - волны 3 и контрактные тесты.

## Проверка

```powershell
cd <bridge_root>
python -m unittest discover -s tests -p "test_wave4.py" -v
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\RUN_STATIC_TESTS.ps1 -Root (Resolve-Path .)
```

## Что сделано

### 1. Экспорт с обязательной проверкой (B4)

**Было.** Волна 2 дала `kompas_artifact_check` - проверку файла по содержимому.
Но экспорт и проверка оставались двумя разными вызовами: агент мог объявить
задачу выполненной сразу после экспорта, а файл при этом был пустым или
обрезанным. Метод экспорта в КОМПАСе возвращает управление без исключения
в обоих случаях.

**Стало.** `src/export_tools.py` и инструмент `kompas_export`. Экспорт и
проверка объединены: **файл считается экспортированным только если он прошёл
проверку по содержимому**.

Как это устроено:

* форматы `step`, `dxf`, `pdf`; имя файла - только basename внутри рабочего
  каталога, суффикс обязан соответствовать формату; существующий файл не
  перезаписывается;
* `apply=false` - сухой прогон: возвращает план и список имён методов,
  которые будут испробованы, **не делая ни одного обращения к COM**
  (проверяется тестом со счётчиком вызовов);
* после экспорта файл прогоняется через `artifact_check`, и вердикт попадает
  в ответ; `ok: false` - операция считается неудачной;
* файл, не прошедший проверку, **не удаляется** - его нужно посмотреть, а
  удаление скрыло бы улики;
* `SaveAs` намеренно исключён из списка методов: он сохраняет сам документ,
  а не выгружает копию, и ошибка в аргументах может перезаписать модель;
* интерфейс экспорта не подтверждён на стенде, поэтому имена методов
  перебираются, фактически сработавший путь возвращается в
  `interface.method`, а если не сработал ни один - поднимается
  `export_interface_not_available` со списком попыток.

### 2. Контрольные точки (D5)

**Было.** Снимки перед записью делались в каждом инструменте своим кодом:
`shutil.copy2` в каталог `_BACKUPS` с именем из `uuid4`. Их нельзя было
перечислить, они копились бесконечно, а откат существовал только внутри
того вызова, который снимок сделал.

**Стало.** `src/checkpoint.py` и инструмент `kompas_checkpoints`:

* `list` - список снимков с флагом `exists`, фильтр по файлу;
* `restore` - возврат снимка на место исходного файла; требует точный id и
  совпадающее имя файла, работает только внутри разрешённых корней;
* `prune` - уборка старых снимков сверх лимита с подсчётом освобождённого
  места;
* индекс пишется атомарно (`tmp` + `os.replace`), поэтому прерванная запись
  не оставляет битого журнала.

### 3. Найденный и исправленный баг в волне 2

Тесты волны 4 вскрыли настоящий дефект, который не был виден раньше:
вспомогательная функция `_attr` **вызывает** найденное значение
(`value() if callable(value) else value`). Для COM-свойств это верно, но
для методов вроде `ExportToFile(path)` или `AddMateConstraint(...)` вызов
без аргументов давал `TypeError`, исключение молча гасилось, и всё выглядело
как «метода нет».

Это означает, что `kompas_mate_create` из волны 2 **не работал бы** на живом
КОМПАСе: он всегда возвращал бы `mate_create_interface_not_available`, даже
если нужный метод есть. Тесты волн 2 и 3 этого не замечали, потому что
проверяли чистые функции и каталог, а не COM-слой.

Исправлено введением `_method()` - получения вызываемого метода без вызова:
в `_export_call`, `_create_mate` и `_find_collection` (`mate_tools.py`).

Вывод на будущее: COM-обёртку нужно проверять на подставном объекте, а не
только на чистых функциях. В тестах волны 4 так и сделано - используется
`FakeCom` с методами, записывающими реальные файлы.

## Изменения, заметные оператору

1. **Поверхность выросла с 40 до 42 инструментов:** `kompas_export`,
   `kompas_checkpoints`. `VERSION.json` обновлён.
2. **`kompas_export` по умолчанию ничего не делает** - `apply=false`. Первый
   вызов на новой сборке КОМПАСа безопасен именно поэтому.
3. **`kompas_checkpoints` помечен как разрушительный** (`destructiveHint`,
   потому что `restore` перезаписывает файл. Клиент запросит подтверждение -
   это осознанно.
4. **Существующий файл экспорта не перезаписывается.** Если `out.step` уже
   есть, вызов отклоняется до обращения к КОМПАСу.
5. **Тесты-«стоп-краны» с числом инструментов обновлены** в `test_wave1.py`,
   `test_wave2.py` и `test_wave3.py` - теперь 42.
6. **Версия сборки по-прежнему не поднята** - `1.1.14_CAP2`, по той же
   причине, что и раньше: строка зашита в десяти местах, включая сборку
   golden-пакета.

## Чего в этой волне нет

* чертежи, основная надпись, экспорт DXF как операция над чертежом (B2);
* спецификация как документ (B3);
* обратный импорт STEP и сверка габаритов - экспорт проверяет только
  целостность файла, а не совпадение геометрии;
* dry-run для всех остальных мутирующих инструментов (D4): сейчас он есть
  только у экспорта;
* устойчивые ссылки на объекты (D2), самокалибровка кадра (D6);
* упаковка, CI, лицензия (E1-E3).

Отдельно про миграцию на `checkpoint.py`: остальные инструменты пока делают
снимки старым кодом. Модуль совместим с ними по формату каталога
(`_BACKUPS`), поэтому переход можно делать инструмент за инструментом - это
не требует одновременной переделки всего проекта.

Актуальный список приоритетов - в отчёте `KOMPAS-3D_AI_Bridge_audit_plan.html`.
