# Волна 5: 2D-документы, основная надпись, спецификация

Поверхность инструментов: **42 → 46**.

Патч `wave5.patch` накладывается поверх `wave1` + `wave2` + `wave3` + `wave4`.

## Зачем

Мост закрывал 3D полностью, а 2D-сторона КОМПАСа — чертежи, фрагменты,
основная надпись, спецификация — не была доступна агенту вообще. При этом
унаследованный код в `src/capabilities.py` **умел** читать листы и штамп:
действия `sheet.info`, `stamp.read` и `stamp.write` там есть. Но ни один
инструмент каталога на них не ссылался, то есть через MCP они были
недостижимы. Это не «новая функциональность», а выведенная из тени
существующая — с нормальной валидацией и проверкой записи, которой в
унаследованном виде не было.

Отдельная проблема: спецификация вообще не существовала. `kompas_bom_read`
давал состав сборки, но не раскладывал его по разделам ГОСТ.

## Что добавлено

### `src/drawing_tools.py`

| Инструмент | Действие | Что делает |
|---|---|---|
| `kompas_drawing_info` | `drawing.info` | Листы, формат каждого листа, инвентарь видов |
| `kompas_stamp_read` | `stamp.read` | Чтение ячеек основной надписи по номерам |
| `kompas_stamp_write` | `stamp.write` | Запись ячеек с проверкой и откатом |

### `src/spec_tools.py`

| Инструмент | Действие | Что делает |
|---|---|---|
| `kompas_specification_read` | `specification.read` | Раскладка спецификации по разделам ГОСТ |

## Ключевые решения

**Мост не называет ячейки основной надписи.** Нумерация зависит от стиля
основной надписи в конкретном шаблоне. Выдуманный словарь «1 = наименование»
дал бы правдоподобную, но неверную картину на чужом шаблоне — и агент начал
бы писать «наименование» в ячейку, которая означает совсем другое. Поэтому
инструменты работают номерами: `kompas_stamp_read` без аргументов читает
первые 60 ячеек, чтобы оператор один раз сопоставил номера своему шаблону.
Метки можно объявить в конфиге, по умолчанию их нет.

**Запись в штамп использует контрольные точки из волны 4.** Перед записью
снимается снимок, затем: запись → чтение всех ячеек обратно → Save → Close →
Reopen → чтение снова. Любое расхождение — откат файла из снимка, в тексте
ошибки указан id снимка и признак `rolled_back`. Это первая мутирующая
операция в проекте, у которой есть настоящий откат, а не только обнаружение.

**Отказ от 3D-документа явный.** Если активен 3D-документ, у него нет
`LayoutSheets`, и инструмент поднимает
`active_document_has_no_layout_sheets_not_a_2d_document` с типом документа,
а не возвращает пустой список листов.

**Несуществующая коллекция видов — это не «видов нет».** Если `CastTo` не
сработал или коллекция не нашлась, в ответе `views_interface.confirmed = false`
с перечнем попыток. Пустой список значил бы «видов нет», и недостающую функцию
приняли бы за пустой чертёж.

**Спецификация помечена как производная.** Мост не читает настоящий документ
`.spw`: объектная модель спецификации (`ISpcObject` и подобные) не проверена ни
на одной установке, а угаданная модель хуже честного отказа. Вместо этого
раздел выводится из нативных признаков вхождений:

- `Standard = true` → Стандартные изделия;
- `IsBillet = true` → Материалы;
- есть дочерние вхождения → Сборочные единицы;
- иначе → Детали;

и количество всегда равно точному числу подходящих вхождений. Позиции
нумеруются мостом внутри раздела и не являются нативными позициями
спецификации. Разделы «Документация» и «Комплекты» из дерева сборки не
выводятся, поэтому никогда не заполняются — об этом сказано в `limits`.

**Перекрёстная проверка.** Производное количество обязано совпасть с
`eligible_occurrence_count`. Расхождение помечает ответ как недостоверный
(`cross_check.ok = false`) и добавляет предупреждение, а не выдаёт раскладку
как верную.

## Границы валидации

- Ячейки: номера 1..200, не более 200 за вызов на чтение.
- Запись: не более 20 ячеек за вызов, текст до 255 символов, без управляющих
  символов (перевод строки в ячейке штампа ломает блок).
- Листы: индекс 0..99, выход за число листов — ошибка.
- Запись требует сохранённый `_AGENT_COPY` внутри разрешённых корней моста.

## Что изменится для оператора

- Четыре новых инструмента в `tools/list`; число инструментов 46.
- Ожидания в `tests/test_wave1..4.py` обновлены с 42 на 46 осознанно — это
  штатный стоп-кран, а не случайная правка.
- `VERSION.json` приведён к порядку каталога; тест
  `test_version_json_matches_catalog` теперь сравнивает порядок, а не только
  множество.
- Унаследованные `sheet.info` / `stamp.read` / `stamp.write` в
  `src/capabilities.py` **не удалены** и по-прежнему недоступны через MCP.
  Новые инструменты их не вызывают.

## Как проверить

```bash
python -m unittest discover -s tests -p "test_wave5.py" -v
python tests/test_mcp_stdio.py          # PASS test_mcp_stdio 46
```

Смоук протокола: `initialize → 2025-11-25`, `tools/list → 46`.

## Что намеренно не сделано

1. Чтение и создание настоящего документа спецификации `.spw`.
2. Именование ячеек основной надписи «по ГОСТу» — нужен живой шаблон.
3. Создание видов, размеров и объектов оформления: это отдельная волна.
4. Подтверждение на живом КОМПАСе: стенда не было, все имена интерфейсов
   подобраны перебором документированных вариантов с честной деградацией.
