# Волна 7 — доменный слой щита (НКУ / АСУ ТП)

Поверхность инструментов **47 → 49**. Патч `wave7.patch` накладывается поверх
`wave1..wave6`.

## Что появилось

Два инструмента и три новых модуля. Оба инструмента — чистые проверки:
документ не открывается, КОМПАС не требуется, ничего не пишется.

| Инструмент | Действие | Что проверяет |
|---|---|---|
| `kompas_cabinet_spec_check` | `cabinet.spec_check` | Состав шкафа, совместимость оборудования, секционирование по ГОСТ IEC 61439-2 |
| `kompas_cabinet_layout_check` | `cabinet.layout_check` | Раскладку монтажной панели: границы, каналы, позиции, зазоры, переполнение рядов |

Новые файлы:

- `src/cabinet_domain.py` — домен: типы шкафа, категории оборудования, формы
  разделения, десять инженерных правил, сбор неподтверждённого и
  непроверяемого.
- `src/cabinet_layout.py` — геометрия раскладки: миллиметры, начало координат
  сверху слева, `+y` вниз; повёрнутые габариты, каналы, ряды, зазоры.
- `src/cabinet_tools.py` — адаптеры к реестру действий.
- `tests/test_wave7.py` — 43 теста без КОМПАСа.

## Почему это не «ещё два инструмента»

Исследование GitHub (102 запроса, три волны) показало: **открытых библиотек
щитового оборудования под КОМПАС-3D не существует вовсе**. По-русски ноль
дают «компас щит», «компас шкаф», «компас НКУ», «компас электрощит»;
по-английски — «kompas cabinet», «kompas3d cabinet», «kompas switchgear».
При этом CAD-возможности для генерации щита в мосте уже есть: из 16 шагов
конвейера проходятся 13.

Не хватало не геометрии, а **домена** — модели щита и инженерных правил.
Волна 7 закрывает именно его. Правила не выдуманы: они перенесены из
`postall74/TaCP` (`src/utils/rules.ts`), соглашения раскладки — из
`Taam4142/cabinet-layout-generator-v2` (`web/src/model/types.ts`,
`validate.ts`). Оба проекта разобраны по исходникам.

## Десять доменных правил

| № | Код | Уровень | Условие |
|---|---|---|---|
| 1 | `BREAKER_OVER_BUS` | error | Номинал отходящего аппарата выше номинала шины. Вводной (самый мощный) исключён из сравнения |
| 2 | `MANY_BREAKERS_NO_BUS` | info | Три и более автоматов без соединительной шины |
| 3 | `UZIP_NO_INCOMING` | warn | УЗИП без вводного автомата или рубильника |
| 4 | `PLC_NO_PSU` | warn | Контроллер без блока питания 24 В в этом шкафу |
| 5 | `HMI_NO_PLC` | warn | Панель оператора есть, ПЛК нет ни в одном шкафу проекта (межшкафное) |
| 6 | `EMPTY_CABINET` | info | Шкаф пуст |
| 7 | `FORM_NO_BUSBAR_SEGMENT` | warn | Форма ≥ 2 без шинного отсека |
| 8 | `FORM_FEW_SEGMENTS` | warn | Форма ≥ 3 при менее чем двух функциональных отсеках |
| 9 | `BUSBAR_OVERLOAD` | warn | Сумма номиналов отходящих автоматов выше допустимого тока шины |
| 10 | `HEAT_NO_THERMOSTAT` | warn | Греющий кабель без терморегулятора (правило на проект) |

Плюс `UNRESOLVED_CATALOG_REF` (error): ссылка на справочник не разрешается —
позицию нельзя ни проверить, ни разместить.

## Ключевые решения

**Ничего не угадывать — и это проверяется тестами.** Правила 1 и 9 физически
не могут сработать без номинального тока. Отсутствующий ток — не «ноль» и не
«проверено»: позиция уходит в `unconfirmed` с причиной
`rated_current_missing`, а сами правила — в `unverified`. Отдельный тест
требует, чтобы шкаф с аппаратом без номинала получил вердикт
`ready_with_unknowns`, а не `ready`.

**Количество в строке состава разворачивается.** «Автомат 40 А, qty 3» — это
три автомата. Без этого три автомата на шине проходили проверку как один.
Найдено тестом: `BUSBAR_OVERLOAD` не срабатывал на qty 2.

**Три вердикта, как в волне 6:** `blocked` (есть error),
`ready_with_unknowns` (есть warn, неподтверждённое или непроверяемое),
`ready`.

**`error` — структурно невозможно, `warning` — разрешено, но показать.**
Перенесено из CLG2: пересечение, выход за панель и тесный зазор не блокируют
запись, но обязаны вернуться в ответе. Ничего не исправляется молча.

**Переворот координат — в одном месте.** Раскладка живёт в системе
«сверху слева, `+y` вниз». Переход в CAD-систему делает только
`cabinet_layout.to_cad()`. Размазать этот переворот по коду — значит
гарантировать перевёрнутый щит.

**Неподтверждённый габарит не заменяется оценкой.** Позиция с
`confirm: true` уходит в `unconfirmed`, а не в «примерно 90 мм».

## Что оператор заметит

- Два новых инструмента в `tools/list`; оба `readOnlyHint: true`.
- Вердикты и коды правил в ответе; для каждого правила есть человеческий
  текст и подсказка, что делать.
- Поле `limits` в каждом ответе: чем проверка **не** является.

## Чего в волне нет

- **Материализации в КОМПАС.** Волна 7 ничего не строит: это волна 9.
- **Вставки фрагмента из библиотеки оборудования.** Главный разрыв, под него
  задумано поле `fragment_ref` в справочнике.
- **Чтения настоящего `.spw`.** Спецификация по-прежнему производная.
- **Расчёта токов КЗ, теплового режима и сечений кабелей.** Это отдельные
  домены со своими нормативами.
- **Экономики.** Состав и трудозатраты — да; цены, наценки и НДС — нет.

## Проверка

```
python -m unittest tests.test_wave7                       # 43 теста
python -m unittest tests.test_wave1 ... tests.test_wave7 \
                   tests.test_mcp_stdio \
                   tests.test_mcp_bridge_routing          # 273 теста
```

Обновлены стоп-краны с числом инструментов: `test_wave1` (49), `test_wave2`,
`test_wave3`, `test_wave4`, `test_wave5`, `test_wave6`. VERSION.json:
`mcp_tool_count` 47 → 49, в `mcp_tools` добавлены два имени в порядке
каталога (порядок сравнивается тестом, а не множество).

Имена тестов-счётчиков в `test_wave5` и `test_wave6` приведены к реальному
числу: они назывались `is_46` и `is_47` при значении 47.
