# Официальный SDK КОМПАС-3D и MCP-слой: состояние на сентябрь 2026

Справка по вопросу «есть ли у КОМПАСа официальный MCP SDK и что через него можно делать».
Составлена по итогам проверки сайта АСКОН, релизных заметок КОМПАС-3D v25, материалов
КОМПАСcon 2026 и поиска по GitHub.

## 1. Короткий вывод

| Вопрос | Ответ |
|---|---|
| Официальный MCP-сервер от АСКОН | Нет. Не существует на сентябрь 2026 |
| Официальный SDK КОМПАС-3D | Да. 2D API и 3D API, доступен разработчикам |
| ИИ-ассистент внутри КОМПАС | В разработке. Анонс на КОМПАСcon 2026 (4 сентября) |
| MCP-слой сегодня | Полностью сторонние проекты поверх SDK |

Важное уточнение: организация `ascon` на GitHub — это криптографический алгоритм Ascon
(победитель конкурса NIST Lightweight Cryptography), а не АСКОН. Не путать при поиске.

## 2. Что такое официальный SDK КОМПАС-3D

Определение с сайта АСКОН: «SDK КОМПАС-3D — это ориентированные на прикладного
программиста инструментальные средства разработки приложений (библиотек конструктивов,
прикладных САПР) на базе системы КОМПАС-3D».

Два независимых интерфейса:

- **2D API** — экспортные функции DLL плюс Automation. Работает с КОМПАС-ГРАФИК.
- **3D API** — стандартные COM-объекты плюс Automation. Работает с трёхмерными документами.

Automation построен на `IDispatch` и, по документации, позволяет реализовать
**весь функционал** систем КОМПАС-ГРАФИК и КОМПАС-3D. Именно этот путь используется
всеми MCP-обёртками, потому что он доступен из скриптовых языков.

### Технические опоры

- ProgID: `KOMPAS.Application.5` (API5 — чертежи, виды, 2D) и `KOMPAS.Application.7`
  (API7 — трёхмерные документы).
- Типбиблиотеки для типизированного доступа из Python:
  - `ksConstants.tlb` — `{75C9F5D0-B5B8-4526-8681-9903C567D2ED}`
  - `ksConstants3D.tlb` — `{2CAF168C-7961-4B90-9DA2-701419BEEFE3}`
  - `kAPI5.tlb` — `{0422828C-F174-495E-AC5D-D31014DBBE87}`
  - `kAPI7.tlb` — `{69AC2981-37C0-4379-84FD-5DD2F3C0A520}`
- Подключение из Python:
  `win32com.client.gencache.EnsureModule("{GUID}", 0, major, minor)`.
- Языки, заявленные производителем: Visual Basic, Visual C++, C++Builder, Delphi.

### Практическое следствие

Одна сессия — одно приложение. Переключение между чертежом (API5) и сборкой (API7)
требует явного выбора объекта приложения, иначе вызовы уходят не в тот контекст.
Это же причина, по которой агент обязан перед каждой правкой проверять активный документ.

## 3. Объектная модель: что доступно

| Документ | Что можно читать и менять | API |
|---|---|---|
| Деталь | тела, грани, рёбра, эскизы, операции, дерево построения | API7 |
| Сборка | состав компонентов, размещение, ориентация, сопряжения | API7 |
| Чертёж | виды и проекции, слои, объекты оформления, размеры, тексты, штамп | API5 |
| Фрагмент | 2D-геометрия, макроэлементы | API5 |
| Спецификация | объекты и разделы, привязка к компонентам | API5/API7 |
| Переменные | параметрические переменные и уравнения | API7 |

Отдельно стоит выделить сопряжения сборки: интерфейс `IMateConstraint`
(реализация `ksMateConstraint`) с свойствами типа сопряжения, направления,
расстояния и признака фиксации; коллекция `IMateConstraintCollection`,
получаемая через `ksDocument3D::GetMateConstraint`. Это тот уровень, который
превращает набор деталей в изделие, и в текущих сторонних MCP-серверах он
практически не закрыт.

## 4. Что из этого превращается в MCP-инструменты

MCP-сервер не должен повторять API один к одному: методов тысячи, модель утонет
в выборе. Нарезка идёт по уровню риска.

**Читать и проверять (безопасно, без изменения документа):**
активный документ и его путь, дерево модели и состав, свойства и переменные,
сопряжения сборки, масса и центр масс.

**Создавать и менять (нужно подтверждение):**
эскизы и операции, компоненты сборки, виды и оформление, объекты спецификации,
перестроение модели.

**Проверять и выгружать (контроль результата):**
STEP, DXF, PDF, STL, снимок экрана модели, проверка коллизий, контроль после
записи, откат к точке возврата.

## 5. Пайплайн агента, показанный на КОМПАСcon 2026

Промпт инженера → LLM пишет скрипт → MCP-сервер передаёт операции → КОМПАС-3D
строит геометрию → проверка зрением (VLM смотрит скриншот) → при расхождении
модель правит скрипт и цикл повторяется → результат принят.

Две лекции 4 сентября 2026:

- **Александр Симаранов («Сверх»)** — агент работает **через MCP, а не напрямую
  с ядром**. Модель двигателя дрона собрана за 4 часа.
- **Даниил Дружинин и Антон Судницын (Мосполитех, стажёры АСКОН)** — встраивание
  агента внутрь КОМПАС с доступом к инструментам системы и поиском по ГОСТ.
  Есть слой **GUARD**, валидирующий сгенерированный нейросетью код. Причина
  названа прямо: из-за огромного API Компаса модель может остановить рабочий
  процесс или непредсказуемо изменить документ.

Вывод: обе команды независимо пришли к тому, что нужен детерминированный слой
валидации между моделью и API. Это подтверждает архитектурное решение,
заложенное в наш план аудита.

## 7. Что это значит для нашего проекта

1. Ждать официальный MCP не нужно — его нет и сроки не объявлены. Но и
   «изобретать» API не нужно: SDK стабилен и полон.
2. Собственный ИИ-ассистент КОМПАС, когда выйдет, будет конкурировать с нашим
   решением, но не отменять его: он встраивается в систему, а наш слой работает
   через MCP с любым клиентом.
3. Приоритеты Wave 2, вытекающие из этого разбора: сопряжения сборки
   (`IMateConstraint`), чертёж и штамп, спецификация, экспорт STEP с проверкой
   импортом, сторож зависших модальных диалогов, матрица поддерживаемых версий.
