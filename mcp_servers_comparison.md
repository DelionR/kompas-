# MCP-серверы для щитового оборудования: сравнение

Данные собраны 19 сентября 2026: поиск по GitHub (16 запросов по MCP +
электротехнике, ~200 репозиториев), каталог MCP Glama, прямые обращения к GitHub
API и чтение README отобранных проектов. Обновлено 21 сентября 2026: разобран
`covagashi/eplan-rag-mcp` и закрыт главный остаток — нормативные таблицы
(волна 13).

## Главный вывод до таблицы

**MCP-серверов для подбора и каталогизации щитового оборудования не существует.**
Это не «не нашёл», а подтверждённый результат:

- `electrical panel mcp` — **0** репозиториев;
- `IEC 61439 mcp` — **0**;
- `electrical schematic mcp` — **0**;
- `electrical component catalog mcp` — **0**;
- `switchgear mcp` — 1 (SwitchScope, 0 звёзд);
- `circuit breaker mcp` — 111, но **ни одного** про автоматические выключатели:
  это мониторинг токенов Claude Code, Telegram-боты и учебные конфиги.

Ниже — то, что реально существует. Ближайшие по теме серверы закрывают
электротехнику **косвенно**: расчёты кабелей, схемы в ECAD, конфигуратор MCC под
AutoCAD. Прямого конкурента нашему серверу нет.

**Уточнение от 2026-09-20.** Формулировка выше относится к *щитовому
оборудованию*, и она подтверждена. Но для **ECAD-системы** MCP-сервер есть и он
заметен: `covagashi/eplan-rag-mcp` — 96 звёзд, MIT, **199 инструментов** по
EPLAN Electric P8 плюс три удалённых RAG по документации EPLAN. Он автоматизирует
**систему**, а не подбор и расчёт щита: схему, устройства, отчёты. Прямым
конкурентом он не является, но задаёт планку по глубине автоматизации САПР,
которой нам далеко не достичь. Из него стоит взять не функции, а четыре
архитектурных приёма — см. одноимённый раздел ниже.

## Чего нет до сих пор

Отсортировано по цене и отдаче. В скобках — нужна ли машина с КОМПАС-3D.

Все три главных остатка закрыты: нормативные таблицы — волной 13,
спецификация и маркировка — волной 14, схема как модель данных — волной 16.
Внутри нормативных таблиц три вещи ещё не доделаны, и они перечислены первыми,
потому что это уточнения уже работающего слоя, а не новые направления:

- **таблица коэффициентов спроса покрывает один тип нагрузки** — в ПУЭ 7-го
  издания таблицы коэффициентов спроса нет, найден только п. 6.3.39; остальные
  типы уходят в `unverified`;
- **время-токовые данные — границы стандарта, а не паспортные кривые**
  изготовителя: для ответственных ответов нужна кривая производителя;
- **в мосте по-прежнему нет MCP-ресурсов вовсе** — таблицы отдаются
  инструментом, а не как ресурсы протокола.

**1. Проверка нагрева НКУ (не нужна машина, нужны данные производителя).**
По ГОСТ IEC 61439-1 оболочка проверяется по рассеиваемой мощности: суммарные
потери оборудования сравниваются с допустимыми для корпуса. У нас ни потерь
аппаратов, ни допустимых значений для корпуса нет — производитель их в открытом
каталоге не публикует. Сегодня корпус подбирается по числу модулей, что
**не заменяет** эту проверку.

**2. Поиск по документам: семантика (не нужна).**
Наш поиск по подстроке: неточная формулировка даёт пустой результат. SwitchScope
ищет по смыслу. Улучшение локальное: индекс, морфология, ранжирование. Ценность
есть, но она не в щитовой логике — делать последним.

**3. STEP → `.m3d` и реальная геометрия изделий (нужна машина с КОМПАС).**
План готов: `docs/STEP_IMPORT_PIPELINE.md`. Пока материализация даёт габаритные
блоки. Главный риск — модальный диалог при импорте.

**4. Запись спецификации, маркировки, шильд в документ КОМПАС (нужна машина).**
Продолжение волн 14 и 16.

**5. Приёмка на живом КОМПАСе (нужна машина).**
Снимок видового экрана, пересчёт габарита, реальная спецификация. Две вещи
честно помечены непроверенными: нумерация экземпляров (`component_count - 1`) и
учёт линейного массива в перечне.

**6. Диагностика через сообщения системы (нужна машина).**
`eplan_get_system_messages` читает дерево сообщений EPLAN — те же ошибки и
предупреждения, что видит пользователь. У нас есть `kompas_dialogs` и
`artifact_check`, но не чтение журнала сообщений КОМПАС.

**7. AAS/AASX — цифровой двойник изделия (не нужна).**
У EPLAN-сервера 4 инструмента на экспорт и импорт AAS/AASX (Industrie 4.0).
У нас ничего. Формат открытый и текстовый: состав щита можно выгрузить в AASX
без КОМПАС. Ценность зависит от того, кому отдаём данные — для обмена с
заказчиком или PLM это весомо, для внутренней работы избыточно.

## Что стоит взять из EPLAN-сервера как приём, а не как функцию

- **Каталог действий вместо инструмента на действие.** У EPLAN ~1 050 GUI-действий,
  но вместо 1 050 инструментов — четыре (`catalog` / `describe` / `run` /
  `ribbon_catalog`). Обоснование в README прямое: иначе список инструментов
  утроился бы и подбор нужного деградировал. Тот же приём мы уже применили в
  `kompas_cabinet_calc` (поле `kind` вместо восьми инструментов) — стоит держать
  его и дальше.
- **Режим discovery.** 13 инструментов вместо 199 для клиентов, которые шлют все
  схемы на каждый запрос. У нас 59 — пока терпимо, но при росте пригодится.
- **Отдельный файл для модели.** У проекта есть `llm.md` — описание возможностей
  в терминах, рассчитанных на языковую модель, отдельно от человеческого README.
  У нас такой роли нет: документация волн написана для инженера.
- **Документация вендора как RAG.** Три удалённых сервера ищут по официальной
  документации EPLAN. Наш `kompas_docs_search` ищет по файлам проекта: чтобы
  получить то же, достаточно положить документацию КОМПАС в доступный каталог —
  инструмент уже умеет.

## Брать не стоит

- **Каталоги и 3D-модели производителей в составе продукта.** Лицензии обычно
  «для проектирования», перераспространение запрещено. Данные можно снимать с
  открытых карточек как пример (это сделано), включать в продукт — нельзя.
- **Расчёт сети с ветвлением (OpenDSS).** Это расчёт сети, а не щита: тащить
  движок ради одной петли несоразмерно.
- **Средневольтные КРУ (SwitchScope).** Другой класс напряжения и другие нормы.
- **Привязка к чужим САПР.** AutoCAD Electrical и MCC-конфигуратор живут на
  шаблонах DWG конкретного предприятия; наш путь — КОМПАС.

## Рекомендация

**Оставить и дополнять. Заменять нечем.**

Обоснование прежнее: прямого конкурента не существует — ни один найденный сервер
не закрывает щитовой домен. Наш — единственный, кто умеет состав, компоновку,
материализацию, сверку, расчёт и подбор щита в КОМПАС-3D, и это не теряется ни
при каком варианте. Проверено 645 тестами.

Пункты прежнего порядка закрыты волнами 13, 14 и 16. Дальше:

1. **Чтение схемы из документа КОМПАС и запись её туда** — модель уже есть
   (волна 16), машина нужна только для чтения обозначений цепей из документа и
   для отрисовки. Из кода без КОМПАС сделано всё, что можно.
2. **Приёмка и STEP → `.m3d`** — на машине с КОМПАС.
3. **Запись спецификации и маркировки в документ КОМПАС** — данные уже
   формируются волной 14, остаётся записать их в документ.
4. **Семантический поиск по документам** — последним, ценность не в щитовой
   логике.

Блокер внешнего использования снят 2026-09-22: исходники опубликованы в
`DelionR/kompas-` под лицензией **Apache-2.0**.
